# Factory contributor rules

Factory is a GitHub Action (`action.yml`), a plugin (`plugin/`: skills, agents, task card, scripts, tests, workflow template) and a bench (`bench/`). Never run Factory Objectives against this repository; the first adopter is a scratch repository.

Use an existing SDK or library before writing your own: for a protocol, a file format, a codec or a provider's API, look first for the official SDK, then for a maintained library whose licence the repository can take, because hand-written protocol code falls behind its standard and every line of it is ours to maintain. Write it yourself only when nothing fits (no library, a licence that does not fit, an unwanted install script or native binary, or output that must be byte-for-byte deterministic), and say in the PR what you looked at and why it did not fit, then add it to `docs/PLAN.md`'s Dependencies list; a PR that hand-writes such code without that is a review finding. A runtime library ships vendored in `plugin/vendor`, the same section says how.

Read `docs/PLAN.md` (what Factory is, its contracts, 0.9.x releases and the 1.0 bar), `docs/LOCAL.md` (local mode: setup, sandboxes, settings), `docs/ADAPTERS.md` (third-party adapter contracts: the cloud sandbox and the decision model) and `bench/README.md` (the scorecard and drills). Docs describe Factory as it is now; git is the history, so write no logs, dated narratives or ledgers. Code decides on structure only: JSON the harness writes, GitHub fields, exit codes, counts; never prose. Tests: `node --test plugin/test/*.test.mjs bench/test/*.test.mjs`; each test file that touches the file system imports `plugin/test/temp.mjs` first (its temp files then live in a root removed when the file ends), and CI fails when the suite leaves anything in the temp folder.
