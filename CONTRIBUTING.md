# Contributing

The contributions Pendulum wants are issues: bugs, questions and ideas. The most useful report there is is a real Objective that Pendulum handled badly: one it Blocked on for no good reason, asked a Question it should have settled itself, merged wrong, or ran far over what it should have cost. Open one with the [issue forms](https://github.com/clockgrove/pendulum/issues/new/choose); they ask for what is below.

## Reporting a bug

[Open a bug report](https://github.com/clockgrove/pendulum/issues/new?template=bug.yml) with:

- the Pendulum tag your workflow pins (`clockgrove/pendulum@vX.Y.Z`), the harness (Claude Code, Codex or Copilot) and the route (Actions, local mode or the cloud sandbox);
- what you expected and what happened, with a link to the Objective's issue or PR when it is public;
- the Blocked or Question comment's text, and `/pendulum:pendulum-doctor`'s lines when setup is involved.

Leave out tokens, keys and private code. Report a security problem privately instead (see [SECURITY.md](SECURITY.md)).

## Questions and ideas

[Open a question](https://github.com/clockgrove/pendulum/issues/new?template=question.yml) for these. Say what you are trying to do, and what you tried.

## Pull requests

Pendulum takes no outside pull requests until its owner says otherwise, through 0.10.x and 1.0 alike; only maintainers open them. The reason: until 1.0, Pendulum is built by its maintainers' coding agents, each change through a tight loop of CI and review that an outside pull request does not fit. An issue that shows the problem is the way to get a change made.
