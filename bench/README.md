# Pendulum bench

The scorecard, the blind pairwise judge and the auto-grader. Plain Node 22, no dependencies beyond `gh` (logged in, for anything that reads GitHub; `gh run download` unpacks artifacts).

## The row

One row per Objective, read from the issue, the PR on `pendulum/<issue>`, the job log and the usage artifact (`pendulum-usage-<issue>`, plus `pendulum-usage-<issue>-review`):

| Number | What the row says | Taken from |
| --- | --- | --- |
| Walk-away | `yes`, or `no` with the first human action | Binary. The clock starts at the first removal of `pendulum:draft`, or the first legacy Objective label applied outside Draft. Any human push, comment, review, edit or draft/ready toggle on the branch or the issue after it breaks it. Edits of the issue and PR bodies are every edit GraphQL lists (`userContentEdits`), each by its own editor, so a later edit never hides an earlier one; Pendulum's own login's edits (the finish block on the merged PR's body) are not input. A person's `workflow_dispatch` or re-run of the Pendulum workflow (`--workflow`, default `pendulum.yml`) between the clock and the merge is input too: one whose jobs name Objectives counts for those, one that names none (a hand-started dispatcher tick) for every Objective in flight then. The adopter drill's own dispatch (`drill.mjs --dispatch`) is not input for the Objectives it filed: the drill records the run id GitHub returned on each of them (`<!-- pendulum:N:drill {"dispatch": ID} -->`, posted by the issue's author), and that run's first attempt, started by the same login, is the drill's. A re-run of it, or any other dispatch, still counts. A Blocked card (label or marker comment) is a miss; an answered Question is a miss, named as such, even when the answer is nowhere the scorer reads (Pendulum resumed after its Question). A workflow hand-over is scored by `--handover` (Workflow hand-over, below): by default it is normal work, an owner step shown apart, never input. `*[bot]` actors never count; `--bot LOGIN` adds another. Each human action is also split: *asked for* when it follows a Question, Blocked notice or review request Pendulum made and comes before Pendulum's next `pendulum:running` label, else *unprompted* (an owner's note, scope added after the label). The row carries `walkAway.interventions` (`asked`, `unprompted`, Pendulum's `requests`) and `walkAway.askedOnly`, walk-away counting only asked-for actions; the table shows both, and the line under it sums them. A merge that sat idle longer than the stall threshold (`--stall-minutes`, default 60) between Pendulum's acts is a stall, not a walk-away (`walkAway.stall`; every merged row carries `walkAway.longestIdleMinutes`): the rule, what counts as Pendulum's acts and as idle, is the pendulum-score skill's, in `plugin/skills/pendulum-score/reference.md` (Stalls). Pendulum's posts are told from a person's by their `<!-- pendulum:... -->` markers (in local mode Pendulum posts as the operator's login, and an unmarked comment, a label other than Pendulum's state labels and Pendulum's own `pendulum:handover` (applied with its hand-over comment on the issue or inside a run; removed inside a run only as its drop: the comment then carries no patch, or Pendulum applies the label again; any other removal is the person's mark that they applied it), or removing `pendulum:blocked` without a re-applied Objective label is the operator's). The PR closed by its merge, its branch deleted and the issue closed right after it are the merge's, never acts of their own. |
| Solution quality | `pending` with the pair for the judge | The judge's, never the scorecard's. With `--baseline REF` the row carries the `judge.mjs` command for the merged head against it; without, the owner's read of the merged diff. The row also carries a `grade-auto.mjs` command for the merged head against the PR's own base commit. Escapes found after merge go in `quality.escapes`: an issue labelled P1, opened after the merge, that references the merged PR is filled in, a P1 Objective filed to fix it included; add others by hand. `--append` keeps the hand-filled ones (once per `owner/name#N` they name) and replaces the found ones with this run's, so one whose P1 label was removed drops out. |
| Operator minutes | `0`, a number, or `unknown` | `--minutes <issue>=<n>` from a stopwatch; `0` on a clean merge; otherwise `unknown`, never estimated. A workflow hand-over's owner step has its own minutes, apart from these (Workflow hand-over, below). |
| Cost | dollars with unit and basis | Claude: `usd` from `total_cost_usd` + `modelUsage` (sub-agents in). Codex: `usd` from its tokens priced from `plugin/scripts/lib/codex-prices.json` (the worker's own table), OpenAI's Standard rates as its pricing page and model pages give them, with the date and sources (a project on the Fast Service Tier pays 2× them (2.5× on gpt-5.5, 1.8× on gpt-5-mini), which Codex does not report); a model matches by its exact id (a provider prefix such as `openai/` stripped), a dated snapshot of it, or an alias OpenAI documents (`gpt-5.6`), else its runs are of unknown cost; a promotional rate (`until`) prices only a record that ended before that day, and a later one or one with no `ended` is of unknown cost (a stage's record ends with its latest pass or call); the tokens of a request over 272K input tokens are at the model's long-context rates, which the worker reads request by request from the thread's rollout into the record's `tokens.long`, and a record past 272K without that share (one the worker could not read, or written before it did) is of unknown cost for a model with such rates; a stage's Codex sub-agent threads (`subAgents` in its record) are priced at their own models and the rest of its tokens at the stage's; a run with no completed turn reports no tokens, so its dollars are unknown and its basis says that (`unknown: no Codex turn completed, so Codex reported no tokens`, the worker's record and the exit line alike), never a missing price; the unit stays `tokens` only while unpriced. Copilot: `usd` from the AI credits its `--usage-output-file` reports, at the run's `copilot_credit_usd` (GitHub's published $0.01 per credit by default), with the premium requests beside them (`cost.premiumRequests`, `cost.aiCredits`); an artifact without credits is of unknown cost. How the dollars are billed comes from each record's or spend line's `usdByBilling` and `billing`, which the worker writes on a positive sign only (docs/PLAN.md), never from the figure (`cost.usdByBilling`; a re-priced Codex part takes its record's `billing`): billed per use on a key is the bare figure; Claude Code's `total_cost_usd` or Codex tokens on a subscription are "API-equivalent at list prices, on the subscription"; Copilot's are "Copilot AI credits, billed to the seat"; anything else is "billing not recorded"; an Objective that mixes them shows each part in the cell and the basis. A record from before Pendulum named billing carries none and reads bare. Reviewer artifacts are summed with the worker's. A stage that ran in a cloud sandbox carries the vendor's cost in its record (`vendor`, at the vendor's dated list rates, docs/ADAPTERS.md "Vendor cost"); it is summed beside the model's dollars as `cost.vendorUsd`, with `cost.totalUsd` for both, and the cell reads `model + sandbox = total`; a stage whose usage the vendor did not report is a run of unknown cost there, never its session's ceiling. The dollars are every stage's on every route, each once: the usage artifacts (GitHub Actions, the cloud sandbox) and the `<!-- pendulum:spend -->` lines in Pendulum's own progress comments (local mode uploads no artifact), as the worker priced them; a progress comment of a record's own stage (work or review) that the record names counts as that record, whatever order the records come in: by its `progressRun` (the comment's key; null when the stage had no comment), else, for a record from before `progressRun`, by the sandbox stage's claim (`vendor.claim`, the key's `-<claim>`) or the workflow run that uploaded the artifact (the key's `<run>` or `<run>-<attempt>`), else, for a local `result.json` with no `progressRun` field on an account, that account's comments of its stage. A record Pendulum wrote for a stage whose own process wrote none (`standIn`) gives way to the stage's comment, or, when the stage's own record took it, gives that record its sandbox cost and is dropped. A record that names no comment counts beside the comments, but never doubles a figure: one with no `progressRun` field (a local `result.json` from before records named their comment) beside an unnamed comment of its stage with dollars may be that stage, so its dollars are unknown there (`unmatched`) and the comment's count once. The cost of this exactness is an unknown run, never a known figure twice: such a record and its comment show the comment's dollars plus one run of unknown cost, and a local stage killed before it wrote its `result.json`, scored with `--usage`, adds a run of unknown cost beside its comment. Beside artifacts, a stage's comment with no artifact and no spend line (an artifact that expired) is a run of unknown cost. A relayed worker key's dollars are inside each line's `usd` (broken out as `workerKeyUsd`, counted once), and a stage without a line is a run of unknown cost; a line's `usdUnknown` (runs whose spend no harness or vendor reported: killed, crashed or hung passes, a zeroed result, a model with no price row) is carried into the total; a sandbox stage's vendor dollars are the spend line of its vendor comment (`<!-- pendulum:<n>:vendor:<stage>:<key> -->`), beside its progress comment's. AI Gateway decision calls: a stage's are in its record's `usd` (apart as `gatewayDecisionUsd`, kept as the gateway reported them when a Codex stage's tokens are priced again), and those made outside a stage (the dispatcher's, the launcher's, a local loop's answer, comment, edit and lapse checks) are the `<!-- pendulum:decision-spend {...} -->` lines in Pendulum's own comments on the issue (a notice or record the check wrote, or a role's `<!-- pendulum:<n>:decisions:<role> -->` comment), added to the row on every route, as `api` (billed to the gateway key). Spend that a harness or vendor did not report is shown as unknown, as "plus N runs of unknown cost" beside the known dollars (`cost.usdUnknown`, its reasons in the basis), never as $0, an estimate or a bound; it is not counted against `max_usd` or `daily_usd` either, so a cap can be exceeded by it. Runner minutes and wall time (label to merge) sit beside it; wall time is never alone. |

A missing input shows as `missing: <which>` in the row, never as a guess.

Beside the four numbers the row carries, from the same sources: `phases` (setup and install, model, CI-wait, review-beside-CI and other minutes, read from each run's progress comment; each minute counts once, in the phase of the progress line before it, and the minutes the reviewer runs while the required checks it runs beside are still going are review-beside-CI, in neither model nor CI wait), `dispatch` (for each run, the seconds from the GitHub event that started it to its progress comment appearing, on every path; the latest trigger since the previous run counts, and a run no event explains has none. A work stage that waited for a concurrency slot is timed from the tick that started it, the sandbox record's launch entry or else the Actions run that launched it, and the wait is reported apart as `slotWaitSeconds`, but only when that tick freed a slot (a Pendulum PR merged, or a job's or stage's end tick not of the Objective's own); a later cron or own-stage tick stays in dispatch seconds and is named as `tickEvent`, as does the wait of an Objective the dispatcher had already picked before that tick: sent back to Queued after a failed start (`tickEvent` `requeued`), or still Running after a lost launch it launched again (`relaunched`). Only Pendulum's own marker comments are read: its App's login from `--app`, else the App that applied `pendulum:running`), `phases.setupSeconds` (each run's setup in seconds, from its progress comment to the usage record's harness start; the largest per Objective), `activity` (turns, harness calls, distinct sessions, work and review run counts, read from the usage artifacts), `models` (the harness's worker model as it reported it, the sub-agent and reviewer models, and `labels`, the harness and model labels that chose them, empty on the repository's defaults: each usage record's `ran`, from `result.json` or a local stage's `<!-- pendulum:harness -->` line), `accounts` (the local accounts its stages ran on, by name, from the same records' `account`; empty off local mode), `accountUse` (for each of those accounts, its `stages`, their known dollars `usd`, null when none was reported, and its `limitPauses`, the stages a usage limit paused on it: a local stage's spend line `limitPaused`, or a `result.json` that ended `paused` with its `usageLimit` (or `waiting`, a stage on GitHub Actions or the cloud sandbox that went on on another account); from the usage given and every local stage's progress comment together, a comment whose stage a given `result.json` names by its `progressRun` counting once, as that record), cost by component (uncached, cached, written and output tokens, and a per-model split), and the harness CLI version. The row also carries `rebases` (the send-backs: Pendulum's notices on the Objective's PRs, and from its rebase stages' `<!-- pendulum:rebase-cost -->` lines their count, known dollars with their sandboxes', the runs of unknown cost among them (`unknown`) and conflict passes; the dollars are also in the row's cost). The table shows them as Dispatch s (max), Slot wait s, Setup s (max), Model min, CI wait min, Review beside CI min, Turns, Runs, Sessions and Rebases (`<send-backs>, $<rebase dollars>`, with `plus N runs of unknown cost` when any rebase's spend was not reported), the cost cell as `$ (in / cached / written / out)`, and the Harness cell as `<harness> <worker model>; sub-agents <model>; reviewer <model>; accounts <name> (<stages> stages, $<dollars>, <n> limit pauses), … (by label: …)`.

## Workflow hand-over

Pendulum never pushes a change under `.github/workflows/` and its App has no workflows permission, so an Objective that needs one hands that part over (docs/USAGE.md, Workflow changes). Each merged PR of the Objective whose body carries Pendulum's hand-over line (`<!-- pendulum:N:handover-line -->`; every part of a split Objective) leaves a person's step at that merge. `--handover` sets how the run scores it, for every row and repository:

- `owner-step`, the default for every repository: the hand-over is normal work. When Pendulum's hand-over comment with the patch is on the issue, the Objective can still walk away, and applying it is the row's `ownerStep`: `steps` (each PR's merge), `applied` (the person's removal of `pendulum:handover` after the merge, which is part of the step, not input; `null` until then, and again once Pendulum applies the label for a later part's patch), and `minutes` from `--owner-minutes <issue>=<n>`, a stopwatch, else `unknown`. Operator minutes stay `0` on such a merge. A hand-over whose comment is not on the issue, or is not Pendulum's own (its App's login, from `--app` or the App that applied `pendulum:running`; in local mode the operator's marker comment), is no owner step: each step is one human action, as under `input`.
- `input`, the strict read: each step is one human action at that merge, asked for (a `workflow hand-over` request at the same time), so the Objective is a miss, and its minutes are operator minutes from `--minutes`.

Why `owner-step` is the default rather than an opt-in: under `input` an Objective that needs a workflow change can never walk away, however well Pendulum did, because the boundary that hands it over is Pendulum's own design and stays; that pushed adopters to split such Objectives by hand, which is worse for the record and no safer. Scoring it as an owner step, like a publish, measures what Pendulum controls and still shows the person's step and its minutes. One rule for every repository keeps the pooled 1.0 streak one rule; `--handover input` gives the strict read beside it. A hand-over that needed fixing when applied is an escape: file it P1 referencing the PR, or add it to `quality.escapes` by hand. An Objective whose whole change is the hand-over has no PR and Blocks, a miss under either rule.

Each row records the rule it was scored by (`walkAway.handover`), and the JSON its run's (`handover`). The table's walk-away cell reads `yes, owner step: workflow hand-over`, the Owner step min column gives its minutes (`not applied yet` while the label is on), and the line under the table lists the owner steps, or the hand-overs scored as input. The streak and the pooled streak name the rule in their first line, and a walk-away merge with an owner step reads `yes, owner step: workflow hand-over` in the sequence (`ownerStep` in the JSON).

## Block causes

Every Blocked notice Pendulum posts ends with `<!-- pendulum:block {"cause":"<code>"} -->`. The codes are one closed list, `BLOCK_CAUSES` in `plugin/scripts/lib/logic.mjs`, which says for each whether it is external:

| Code | External | Meaning |
| --- | --- | --- |
| `max-usd` | yes | Pendulum's `max_usd` cap reached |
| `max-objective-usd` | yes | Pendulum's `max_objective_usd` cap reached: the Objective's known spend across its stages |
| `gateway-budget` | yes | the AI Gateway refused for its own budget or credits |
| `provider-quota` | yes | a provider's quota, usage limit, plan limit or billing refusal: the model provider (a subscription's usage limit with no reset reported, or off the local route with its reset past the stage's deadline, after the pass's two waits for it, or with under five minutes of the pass's wall clock left after the reset), GitHub's Git LFS storage (the upload refused for quota or storage), GitHub's API rate limit (spent until a reset past the stage's deadline, off the local route), or the sandbox vendor's plan (still used up after the bounded wait) |
| `outage` | yes | a provider or GitHub outage handled by Pendulum's rules: a required job GitHub never started, waited for in place and then Blocked as infrastructure, in validation or in the merge queue; a red head whose failed jobs failed in their set-up or checkout on a server or network failure (an HTTP 5xx, a timeout, a connection error) naming nothing the PR changes, before and after its one rerun; a stage whose machine could not reach GitHub or the model provider past the outage's bound (twelve hours paused under `serve`, the stage's wall clock on the Action and a cloud sandbox) |
| `setup` | no | a setup gap: a credential or payment method, a secret, a host, an install, any other Git LFS refusal, the repository's settings or rules, the author's access, a token that may not rerun failed jobs, a required check's workflow run GitHub could not start (`startup_failure`) |
| `work` | no | the worker's own Block, validation red, review findings, a protected path, the Objective's size, an edit to the Objective's title or body after its plan (a person's action, never external) |
| `pendulum` | no | Pendulum itself: a crash, a lost or stuck stage, an exit it could not apply, or a cause it did not place |

The row's `walkAway.bucket` is `walk-away`, `external`, `miss` or `unknown`, with `walkAway.blocks` (`{at, cause}` per notice, `cause` null on a notice from before causes). External: not a walk-away, at least one notice, every notice external, no Question, every human action asked for by a Block (`walkAway.interventions`), no stall, every input source read. A notice with no cause line scores as before: a miss. The table's walk-away cell reads `external: Blocked: <codes>`. Unknown: the issue has a label event under the name before the rename to Pendulum (`<old name>:objective` or `<old name>:running`; GitHub keeps a renamed label's old name on its events), so the clock starts at a later label and misses any input, Block, Question or stall before it (`walkAway.clockRenamed`). What it saw after that label is a fact: a miss stays a miss and breaks the streak, and an External result stays External, skipped by the streak as any other, each with its Blocks, Question and human actions as read and its reason noting that the window starts late. Only a result the earlier part could change is not known: a walk-away with every input source read becomes `unknown` (one with a source unread stays as read and breaks the streak) (`value` null; the cell reads `unknown: <why>`), in no walk-away count, the summary line's or the baseline's, and skipped by the streak unless a P1 escape breaks it; an asked-only yes is null. Its operator minutes (but a stopwatch's), waiting and wall clock are unknown.

## The streak

```sh
node bench/score.mjs --streak --repo OWNER/NAME --since v0.10.0 [--append scorecard.json]
node bench/score.mjs --streak --repo OWNER/A --repo OWNER/B --repo OWNER/C --since v0.10.0 [--out pooled.json]
```

Consecutive walk-away merges per harness from a Pendulum tag (its Release's time, read from `--pendulum`, default `clockgrove/pendulum`): the Objectives whose clock started at or after it, in the order they ended. A walk-away merge with no P1 escape and every input source read extends the harness's streak, one with a workflow hand-over's owner step included (Workflow hand-over, above); any human input, a Blocked card, a stall, an unmerged end, a P1 escape in `quality.escapes`, or an input source the scorer could not read (`walkAway.unseen`: the workflow runs without Actions read, or more than GitHub's 1,000 in the window; the body edits without GraphQL) resets it, and the sequence says which. The harness is the usage artifact's, else the `<!-- pendulum:harness -->` line or the `harness <name>` start line in Pendulum's own progress comments; a row with none, or with two (a relabel that switched harness), is listed as `unknown`: it extends no harness's streak, and when it breaks, it breaks every harness's. In local mode a re-run by the operator's login on a head Pendulum's triage record names is Pendulum's own. A re-run of a run created before the first label is not listed. An External Objective is listed in the sequence as `skipped`: it neither extends nor resets the streak and is not counted in `finished` (`external` counts it), unless a P1 escape is later found in its merge, which breaks it. Objectives still running are listed as in flight; ones whose clock started before the tag are left out by number. The adopter's pin is not read: score a repository only while it is pinned to the tag.

The Objectives are the issues that carry `pendulum:objective` (closed since the tag, or open with a Pendulum state label), plus every issue whose label was removed since the tag after Pendulum took it (a state label applied since the tag): a parked Objective, waiting on other work. Its row says `parked` and its exit says where it stopped; it is never a walk-away, and the streak counts it only once it ended (a Blocked one is a miss). The candidates are the issues updated since the tag that do not carry the label now (removing it updates the issue); only their own events are read. Reason: the reads grow with the issues touched in the window, never with the repository's PR and event traffic, and no ceiling can cut the list short.

Several `--repo` values give the pooled streak, the 1.0 bar's (docs/PLAN.md): each repository's streak per harness is printed as above, then one pooled streak over every repository's finished Objectives, in the order they ended, on any harness. A walk-away merge extends it and any miss on any repository resets it; the sequence it counted follows, each entry `owner/name#N (harness) endedAt: yes` or `no: <why>`. `--out` writes `streak.pooled` (`current`, `best`, `walkAway`, `finished`, `sequence` of `{repository, issue, harness, endedAt, ok, why}`, `inFlight`, `before`) and `streak.repositories` (each one's per-harness streak). Options keyed by issue number (`--issue`, `--usage`, `--minutes`, `--read`) and `--md`, `--snapshot`, `--replay` take one repository.

## Prompt cache after a CI wait

Each usage record carries `cache`: the TTL Pendulum asked Claude Code for (`prompt_cache_ttl`, `null` when the CLI default applied), the stage's cache-write share (writes over all input tokens), and, for every validation fix pass (each follows a wait for the required checks), the minutes waited and its first request's split: `first.written` against `first.input`, per `first.unit`. Claude reports a request, and splits the writes into `written1h` and `written5m`, so the TTL actually used is visible. Codex reports a turn, with its writes as `cache_write_input_tokens` (part of `input_tokens`; billed from GPT-5.6 on at the model's write rate in the price table, OpenAI's 30-minute rate, the AI Gateway's `input_cache_write`; earlier models bill them as input); a resumed thread reports its running total, so a resumed pass's split is its own share. A raw Codex `events.jsonl` (no `result.json`) is read the same way: a pass that resumes a thread seen earlier in the stream counts only its own share. Copilot reports only the run, plus the TTL it chose (`harnessTtlSeconds`). The scorecard row sums these under `cost.cache` and the table's notes print one line per Objective.

To decide the setting, score the same medium drill set twice on an API key, once with the default (`off`, five minutes on a key) and once with the workflow's `PENDULUM_PROMPT_CACHE_TTL: auto` (one hour), then compare:

```sh
node bench/score.mjs --repo OWNER/SCRATCH --issue N ... --out ttl-5m.json     # the off run
node bench/score.mjs --repo OWNER/SCRATCH --issue M ... --out ttl-1h.json     # the auto run
jq '[.rows[] | .cost.cache.firstWritten] | add' ttl-5m.json ttl-1h.json     # writes on the first request after CI waits
jq '[.rows[] | .cost.usd] | add' ttl-5m.json ttl-1h.json                    # dollars, which the higher 1h write rate can outweigh
```

`auto` becomes the default only if those writes drop and the dollars do not rise.

## Baseline

```sh
node bench/baseline.mjs --scorecard scorecard.json --repo OWNER/NAME --label wave0 --append   # median and p25..p75 of model minutes, turns, cost (model, sandbox and total), cached and written tokens, CI wait, review beside CI, dispatch seconds, setup, wall minutes and sessions, plus walk-away rate
node bench/baseline.mjs --scorecard scorecard.json --repo OWNER/NAME --since 2026-11-06 --last 5
```

One line per label under `baselines` in the scorecard, so a change's before and after is one command.

## Drill

```sh
node bench/drill.mjs --repo OWNER/SCRATCH --count 2 --dispatch                 # small: one-function additions, merged in minutes
node bench/drill.mjs --repo OWNER/SCRATCH --set medium --count 5 --dispatch    # medium: five Objectives of real size over the scratch adopter's notes CLI
node bench/drill.mjs --repo OWNER/SCRATCH --set conflict --dispatch            # conflict: two Objectives that edit one README section, so the second is sent back to rebase
```

A Question or Blocked exit ends the drill's wait for that Objective. The drill then waits (`--usage-wait-minutes`, default 10) for the usage artifact of each stage Pendulum ran, which can land after the label, downloads every one, and scores Blocked and merged Objectives alike; an artifact that never came is named in the report's `usageMissing` and its row says `missing: usage artifact`. An Objective still running when `--wait-minutes` runs out is not waited for, but its finished stages' artifacts are downloaded and scored, and its running stage is named in `usageMissing` as `(still running)`: its dollars are a floor. The drill files both labels on a scratch repository (never Pendulum's own, never a product repository) and removes Draft when each issue is ready. It follows the dispatcher, waits, and scores the Objectives. The medium set is the instrument for changes to the worker's skills; the reviewer's is `bench/review-replay.mjs` against the private replay set.

## Sandbox check

```sh
node bench/sandbox-check.mjs                          # srt, Claude Code, Codex and Copilot, as local mode configures them
node bench/sandbox-check.mjs --harness srt,codex      # the two that need no model call
```

Local mode's sandbox bar, probed on this machine. One probe script runs under srt (Pendulum's own commands) and under each harness's own sandbox, and every result is checked: the credential store unreadable, writes only in the clone and the stage directories (the clone's hooks and config, the stage's `bin` and another stage's temp directory not), escapes to /tmp and the home directory looked for on the host, the allow-listed host reachable for GET and POST and others not, no model key in the commands' environment, `TMPDIR` inside the stage's private temp directory, pnpm's lock directory writable, and the npm, pnpm, Bun and Yarn caches writable. Claude Code and Copilot take one model call each. On Windows it checks that local mode refuses and names WSL2.

## Skills, versioned

`node bench/skills.mjs` records every plugin skill (SHA-256, lines, words of its SKILL.md, and the same for each other file in its directory, such as a `reference.md` it loads on demand) in `bench/skills.json`. The file holds only those per-skill entries, each on lines of its own, so two PRs that change different skills merge without a conflict there; the one digest that names the skill set is computed from the entries wherever it is read, and the script prints it. Every skill change re-records and commits `bench/skills.json` in the same PR: CI runs `node bench/skills.mjs --check`, which fails when the recorded entries differ from the skills in the tree. Both forms fail when a SKILL.md is over the one-page cap (60 lines, 700 words). Both also fail when a skill, one of its files or an agent definition names something an installed plugin does not hold: an install copies `plugin/` alone, so a skill writes a plugin file from `<plugin root>/`, a tool the plugin does not ship (this bench) from `<pendulum clone>/`, saying up front that it needs a clone, and a page a person reads as a link at a release tag; Pendulum's `docs/`, `bench/`, README or a path from the checkout's root (`plugin/…`) is refused. The setup skill walks local mode from its own `local.md`, and a bench test holds every command, path and example in it to one `docs/LOCAL.md` gives. Detail a run looks up rather than follows every time goes in a reference file beside the SKILL.md, which names it with a pointer saying when to load it; every route that installs a skill copies its whole directory. Each scorecard row carries the digest of the `bench/skills.json` in the checkout that scores it (`skills.digest`), so the row names the skills that checkout ships.

## Score

```sh
node bench/score.mjs --repo OWNER/NAME --issue 811 --issue 812            # table on stdout
node bench/score.mjs --repo OWNER/NAME --since 2026-11-01 --append scorecard.json   # every closed Objective; standing card
node bench/score.mjs --repo OWNER/NAME --issue 811 --usage ./usage-811 --minutes 811=12 --baseline main~3 --out 811.json
```

Artifacts download through `gh run download` with the `gh` login (needs `actions: read`); `--usage DIR` reads `result.json` or `events.jsonl` from disk instead: `DIR/<issue>/` per issue, where an issue without its own directory has no usage (never the other issues'), or one artifact's unzip when one issue is scored. `--snapshot FILE` writes every GitHub answer used; `--replay FILE` scores from it without a token. `--append` replaces the rows of the same repository and issue and keeps the rest.

## Judge and auto-grader on two branches

```sh
gh repo clone OWNER/NAME widgets && gh issue view 811 --json body -q .body > objectives/811.md
node bench/judge.mjs --repo widgets --a pendulum/811 --b main~3 --objective objectives/811.md \
    --judge 'node graders/widgets-judge.mjs' --out judgments/811.json
node bench/grade-auto.mjs --repo widgets --commit pendulum/811 --base main~3 --objective objectives/811.md \
    --check "pnpm check" --check "pnpm test" --out grades/811.json
```

`judge.mjs` runs the judge blind (which ref is A comes from a hash of the two names) and unblinds the answer to refs. `judge.mjs` and `grade-auto.mjs` take the flags in their headers. Tests: `node --test 'bench/test/*.test.mjs'`.
