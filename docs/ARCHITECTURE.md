# Factory architecture

Factory turns an approved Objective in a target repository into a reviewed Work Item graph, exact-tree results and guarded GitHub delivery. It is a plugin and CLI, not a hosted service. Never execute it against its own source repository.

This is a conceptual map. Update it when subsystem ownership or the lifecycle changes, not for ordinary fixes. Exact interfaces and validation rules live in the code; commands and recovery instructions live in the [user guide](USER-GUIDE.md).

## Delivery flow

```text
Objective + pinned sources → compile and review → project Work Item graph
  → schedule → execute → validate exact tree → review acceptance
  → deliver → validate integrated result → seal acceptance → close Objective
```

A compile can split the Objective into child Objectives instead (`src/compiler-wire.ts`, `src/compiler/split.ts`, `src/runner/split.ts`, `src/objective-split.ts`):

```text
compile and review split → create child issues → admit children to the queue
  → each child: plan (or adopt its reviewed graph) → normal delivery flow
  → last child accepted → close parent
```

- **Children and stubs.** A child with no sibling dependencies is ready: the same compile gives it a full graph, and the parent's graph review checks the split, the stubs and those graphs. A child with dependencies is a stub (goal, outcomes, sources, dependencies). It is compiled later, by the normal compiler against the default branch that holds its dependencies' merged code, and gets its own graph review.
- **Acceptance partition.** Every parent Acceptance criterion becomes an Acceptance outcome of exactly one child. When every child is accepted, every parent criterion has been accepted.
- **Child issues.** A child issue keeps the parent's other sections unchanged, so it plans under the same authority. It is a Feature sub-issue with `factory:objective`, blocked by the siblings it builds on. It is created under the existing projection receipts.
- **Queue gating.** Children are admitted to the queue, which holds each one on its native dependencies. A child runs on its parent's provider.
- **Adoption.** A ready child adopts its reviewed graph only while nothing its Work Items own has changed on the default branch since the parent's base. The adopted graph must still verify against the child's own body and sources. Otherwise the child plans afresh.
- **Parent.** The parent's own run ends once its children are admitted. Its continuation records the child issues, and it closes after the last child.

The target owns requirements, validation commands, permissions, protection rules and acceptance. Factory coordinates that work under the approved configuration and recorded limits; it never grants itself deployment, provider, retry or spending authority.

## Planning and evidence

Pin the Objective, default-branch commit and complete cited source contents. Models select semantic choices; code derives canonical identities, hashes, command text and relationships. Providers share the same grounding and validation rules.

The transient compiler wire separates ordinary work from staged media outputs. Ordinary work omits output-media fields; the decoder supplies the canonical empty roles and zero candidates. Media output requires nonempty roles and a positive decimal candidate-count string, strictly decoded to a safe integer in the WorkGraph. This uses provider-supported array and string constraints rather than numerical bounds that some structured-output transports discard. Source assets remain available in either form. Retained items keep their original canonical fields, and semantic media validation remains authoritative.

Compilation and graph review read the repository at the pinned base commit. The model exports every tracked regular file of the base tree (each at most 1 MiB, 64 MiB in total) into a private `repository/` directory without Git metadata, untracked files or network, and gives the session read-only tools over it: Read, Grep and Glob for Claude; the offline read-only shell of the Codex exec source-read and graph-evidence profiles. A deterministic, bounded path map with byte sizes orients both prompts. Routes without file tools (Codex app-server, `sourceArtifacts: false`) receive the map only. Both the export and the map are pure functions of the base commit, so a recovered request renders the same bytes.

A Work Item citation is `{path, heading}`. A pinned citation choice resolves from the Objective's Sources; any other path resolves to the exact UTF-8 bytes of a regular tracked file (or one exact Markdown heading of it) at the graph base, at most 128 KiB per citation and 512 KiB per graph. Every Work Item source, pinned or repository-cited, is persisted by reference: `inputSources` entries are `{path, heading, sha256, bytes}` bound to the graph base, so the graph digest binds the exact content without carrying it. Planner and reviewer views, candidate verification, amendments, work-repair diagnosis, adaptive dispatch context and worker input staging re-derive the bytes from Git at the base (OBJECTIVE from the pinned body; a heading slice from the verified whole blob) and refuse any sha256 or length mismatch. Plan candidates likewise keep only `sourceDigests` and re-derive pinned Sources. Retained graphs from before this change still load, but their inline entries carry no reference, so re-deriving them is refused and such a plan must be planned again. Repository citations grant no command authority: source-declared commands still come from pinned Sources only.

Adaptive planning (retained memory, pinned recipes, discovery and expansions) requires both bounded `planningContext` configuration and an explicit Objective declaration:

```markdown
## Adaptive workflow

enabled
```

An absent or `disabled` declaration retains static planning even when configuration is present. Enabled without configuration refuses before provider calls. The declaration is bound by the pinned Objective body digest; changing it cannot switch a retained run's mode. Retrieval uses the existing PlanningModel seam, with `providerAttemptAdmission: "controller-checkpoint-v1"` required for controller-owned dispatch checkpointing and accounting. Opaque adapters refuse before paid calls. Complete required Sources remain independent of optional retrieval. Context requests reach eligible repository memory and the already pinned Sources; repository files come from the read tools above, and the configured selectors remain the discovery ceiling. Repository, visibility, Objective/path scope and source applicability are checked before ranking and supporting-body reads. Planning can return a context request, graph or explicit human dependency. Required unresolved facts prevent graph compilation, while optional stale or unavailable context keeps its actual disposition. Catalogs describe availability rather than supplying missing content or authority.

The existing planning recovery record retains exact automatic results and request batches, immutable content packet references, elapsed lookup accounting, provider calls and consumed result/byte bounds. Frozen scope and bounds bind a planner session across lookup rounds; each admitted turn additionally binds its exact current packet. Independent graph review receives that same retained context, and recovery authenticates it rather than refetching a replacement. Discovery/retrieval execution and preparation snapshots use versions 9/10 and candidate version 4. Expansion graphs use execution/preparation versions 11/12 and candidate version 5. Declared condition candidates use version 6 and preparation version 14. Execution version 13 admits conditional routing, retained workflow reflection and advanced pending graph semantics before their first durable save; its active graph remains unchanged until reviewed projection settles. Pinned recipe candidates use version 7 and execution/preparation versions 15/16, retaining the original recipe admission binding through later graph amendments. Prior snapshots and candidates remain readable under their original semantics. Version guards prevent adaptive work from silently entering a legacy static route.

Versioned workflow recipes are typed advisory workflow contracts, resolved from an exact regular repository Git blob or the installed package assets. A pinned Objective declaration and configured adaptive admission select them. The controller validates arguments, selector scope and actual prerequisites before retaining original and resolved bytes in ContentStore; compiler and independent graph review receive the same resolved contract. Candidate and continuation bind its original base, configuration, source packet, graph and review identities. Restart loads authenticated retained bytes rather than the latest definition. Recipes constrain declared stages, discovery roles, conditions, expansions and integration dependencies while ordinary source/command/ownership/acceptance rules still apply. Pure preview reports finite ceilings and prerequisite gaps, without inventing task counts, price or latency. Recipe changes and Dream proposals never silently replace an active pin.

Dream uses the same scoped repository retrieval for a bounded selection of settled experience. It retains a complete input packet, included/deferred identities and immutable selection checkpoint before its single explicit provider submission, with a separate active-guidance byte budget. Original episodes, prior guidance, proposals, exact reviewed drafts, decisions and provider receipts remain attributable; accepted proposals retain checkpoint ancestry. Missing completion leaves an unresolved submitted call and prevents blind new consolidation. Routine learning capture has no paid call or background daemon, and guidance promotion remains explicit. Native compaction stays adapter-owned.

Repository memory stores immutable canonical manifests and supporting bodies in existing private ContentStore storage. Provenance distinguishes authority, advisory observations, source identities and versions, applicability, validity, completeness and unknown availability. Approved human decisions retain their verified question/answer bindings; historical verdicts and failure/correction leads never become current acceptance. SQLite/FTS is a derived catalog rebuilt from retained manifests, with eligible manifest scanning when SQLite is unavailable, including early Node 22. Catalog rebuilding changes neither lifecycle state nor acceptance, and native session/worktree disposal does not delete required memory. Without an explicit archive binding these files provide local durability only. The Git checkpoint layer uses typed closure extraction, exact immutable originals and normal guarded fast-forward publication. Independently fetched body verification defines remote acknowledgement; SQLite, derived reports and host resources are not the backup. Neither GitHub progress nor a content digest supplies lost bytes or proves foreign ownership has ended.

Discovery is a distinct Work Item kind with selectors, output role/schema, completeness and finite allowances. Deterministic inventory belongs to the controller; semantic classification requires `ExecutionDriver.readonlyDiscovery: "selector-bound-read-only-v1"` and actual adapter preflight enforcement of a read-only harness profile, initially Codex. Unsupported profiles refuse before paid calls. Its private export contains only the selected immutable source bytes, without Git metadata, network or child-agent access. Output authentication binds producer, exact commit/tree, selectors, body references and completeness. Explicit consumer role/field selection supplies information through ordinary dependency edges without making discovery a code base. Discovery creates no code result, QA proof or delivery authority. Discovery output can drive pinned workflow recipes; portable Git-backed recovery is tracked separately.

Reviewed `WorkGraph.expansions` declarations bind a complete discovery role/schema to literal ownership selectors, a migration or cross-cutting work template, exhaustive selection rules, eligible configured profiles/resources, finite child and batch bounds, dependencies and named integration barriers. The controller groups related regular files into deterministic batches and derives child identities from the exact retained envelope, producer manifest/body and batch. Templates pass the same source, command and profile admission as executable work. They are not independently dispatched. A classified inventory needs explicit included/excluded labels for every in-scope entry; unknown classification, partial input, ownership conflict or excess children stops materialization rather than dropping work.

Each envelope materializes once from an immutable input; changed inputs or semantic choices outside that envelope use supported reviewed amendments or successors. The atomic snapshot retains the exact input packet, desired graph, projected mappings and authenticated settlement. GitHub gateways must implement `projectionMutationAdmission: "controller-checkpoint-v1"`: each expansion projection write is saved before submission, and uncertain submitted effects reconcile through authenticated reads without replay. Initial projection of an expansion plan uses the same fence. Existing static projection retains its established contract.

Controlled graph projection saves each transport observation and authenticated readback locally. The next mutation's pre-effect acknowledgment includes those observations together with its exact new intent. The gateway acknowledges the final complete projection before returning, and retains genuine transport/read failures before yielding. A refused checkpoint retains its original fence without an immediate cleanup retry. This composes local transitions without admitting a mutation ahead of its durable intent.

Both delivery modes hold declared integration barriers and their real dependency descendants until authenticated settlement, then rebuild the graph pass to include every concrete child. Materialization adds actual producer/child dependency edges while preserving the original Objective coverage mapping. Started or completed nodes cannot be rewritten. A complete empty inventory settles the expansion with no children; it does not satisfy or waive substantive implementation, QA or final acceptance. Exact-tree checks, independent result/final review and original repair accounting remain authoritative.

Both schedulers preserve completion and explicit priority, then rank remaining dependency critical paths using one common basis: complete declared duration estimates when all unfinished paths have them, otherwise dependency-stage counts. Estimates are advisory and never grant capacity or alter deadlines. Existing ownership, named-resource, host phase reservations, provider slots and operator holds still determine admission. Diagnostics report those actual blockers, observed whole-item elapsed times and delivery-head replacements; missing queue and provider measurements remain unknown. Shared interfaces, package metadata, lockfiles and configuration have one owner, with dependencies only for actual required changed outputs.

Adaptive implementation requests require `childAgents: "disabled"` through the existing driver/harness seams. Supporting adapters enforce the requested native prohibition; unsupported selected adapters refuse before preparation or provider dispatch. The Codex override participates in its retained-session binding, while static requests omit this policy. Factory continues to schedule independent DAG workers within recorded controller capacity. Existing descendant telemetry is an observation, not shared child admission, complete accounting or proof of cessation. No parent budget is copied to an unreported child.

Role-specific adaptive context is selected automatically at expansion, dispatch, diagnosis and review. Required typed outputs, settled interface bodies, sources and decisions stay complete. Expanded workers receive their bound batch entries instead of the whole discovery inventory. Optional retained memory is scoped and ranked before supporting-body reads, uses the recorded lookup bounds, and preserves current/historical/stale/unavailable dispositions without transferring acceptance. Supplied and shared bodies are reused by exact identity. The existing snapshot retains immutable packet identities, dispositions and ContentStore bytes before dispatch; fresh sessions authenticate the same attributable context, while operational state alone governs progress and effects. Native compaction stays adapter-owned. Cache coordination uses existing native-session capabilities and observed cache counters; no paid cache warm-up is currently supported or claimed.

Declared `WorkGraph.conditions` select already reviewed Work Items through `condition: {conditionId, when}`. Supported predicates are complete inventory emptiness and a semantic classification with exhaustive `otherClassifications`. They require a direct unconditional discovery dependency and authenticated producer, attempt, source and body bindings. Missing, incomplete or unrecognized facts remain held. The existing snapshot retains the exact input packet and selected/skipped disposition before closure; a skip supplies no result, command receipt, acceptance verdict or integration. Original coverage owners, discovery producers and expansion barriers remain unconditional. Final review receives condition facts once, referenced by each routed item, and still proves the original acceptance.

Bounded workflow reflection observes useful settled events through current ownership and receipts. It reuses existing critical-path admission, diagnosis and reviewed amendments; it creates no reflection daemon, mandatory model call, new controller or allowance. Proposals retain the observation, suspected cause, eligible pending scope, expected progress/quality effects, remaining limits and reassessment. Missing timing and causal attribution remain unknown. Active records are bounded, with prior immutable ContentStore references retained for attributable experience; reflection never drives recovery from diagnostics or rewrites started work.

Compilation plans a useful execution DAG rather than minimizing item count. Substantial independently implementable and verifiable components become first-class Work Items with disjoint ownership and settled shared contracts; dependency edges name actual required outputs, not shared decisions or a later combined check. Each feature owner completes its relevant implementation, tests and documentation with acceptance and real proof achievable at its own stage. Shared files have one responsible owner. Full end-to-end obligations normally use authorized integrated validation and one independent final Objective review; final-review coverage may belong to an implementation item without claiming an early pass. Feature owners can author combined checks against settled interfaces, while sibling-dependent execution waits for integration. A downstream implementation item needs an identified deliverable that actually consumes completed peer outputs. Read-only QA supplies named required evidence or material-risk proof absent from final validation/review, including source-required late named CI, rather than duplicating final checks. Required runtime layers, orderings, negative controls and complete evidence remain mandatory. Aggregate children express hierarchy with explicit dependencies. Compiler output contains a short sufficient contract without repeating source bodies or other fields, never truncating required facts. Small cohesive changes remain one item when splitting would not improve the useful critical path; graph review needs concrete grounds to flag avoidable serialization.

Coverage obligations are the Objective's Acceptance criteria plus the exit items the planner extracts from the source sections the Objective pins under Sources. Obligations come only from those human-pinned sources and keep their `sourceIndex` identity in the pinned packet; repository files the planner reads or cites as Work Item inputs (`{path, heading}`) inform the plan but never become obligation sources, so planner reading cannot widen the Objective's required scope. Each extracted item names its exact source and line range and a short statement, and is either proved like an Acceptance criterion or left out of scope with a reason citing Objective lines. Code checks only structure: line ranges exist in the pinned bodies and do not overlap, proofs select existing items, criteria and commands, and cited Objective lines exist. Graph review judges extraction fidelity and exclusion reasons. Final review also judges extracted items proved at the final phase, and amendments keep earlier extracted items as controller obligations with unchanged statements and keep every earlier exclusion excluded or covered.

Work Item repair distinguishes an actual failed-command capture from an explicitly produced semantic acceptance refusal. The existing recovery failure retains the rejected finding or operator decision against its exact tree and criterion, bound to separately retained passing validation receipts. Diagnosis must ground an owned correction in that refusal and complete candidate contents. Missing failed commands do not select the semantic path; unknown evidence remains stopped. Both paths preserve the original attempt and finite repair charge. For a self-contained model refusal after passing validation, diagnosis may omit historical worker input bodies and unrelated pinned source bodies only after authenticating the retained refusal, command authority and complete owned current files against the exact candidate tree. It delivers the original failure and validation, complete owned candidate bodies, relevant authority sources and indexed omission identities inline; tool-free diagnosis does not resolve worker substring selectors. Missing mappings, prerequisites, dependency context or current file evidence use the complete request. Canonical graph inputs, repair evidence, indices, digests and readiness remain unchanged; an omitted body cannot ground actionable repair. Quiet structured-response timeouts surface a retained decision on the first call rather than automatically replaying the unchanged prompt; bounded capacity retries and the existing inactivity limits remain unchanged.

Commands need exact source or verified base authority. Ownership is literal and enforced. Existing acceptance scripts and package-manager/security metadata retain their fixed constraints unless the Objective explicitly authorizes the supported change. Review cannot invent prerequisites, repair quotes into evidence or approve missing facts.

Readiness coverage selects an exact probe and, when supplied sources require it, ordered prerequisite validation rows before that probe. Preparation is authenticated separately in every fresh preflight, worker and final validator checkout; ignored installs and historical receipts do not transfer. The local worker uses the shared validator executor before its provider starts, and drivers unable to authenticate their actual environment refuse such work. Read-only QA executes its authorized setup, probe and checks once in the receipt-owning validator checkout. Preparation receipts never replace semantic acceptance.

Validation runs the approved commands against the exact candidate tree and records its identity and outcomes. Acceptance review starts with its criteria, exact base/result identities and an evidence map. Complete authenticated source and controller evidence remain available in the private read-only workspace; large bodies and historical records need not enter the initial prompt. The reviewer investigates with search and targeted reads, obtaining sufficient evidence for every criterion rather than loading a prescribed repository-wide read set. Claims about absence or preservation may require broader or complete-scope inspection. Missing, incomplete or invalid evidence stays missing, incomplete or invalid; an evidence descriptor or passing unrelated checks does not replace semantic proof.

Installation `reviewArtifacts` selectors are empty by default. An explicit selector binds an exact passed, non-preparation validation command to its JSON stdout receipt, a regular PNG beside that receipt and a tracked candidate file. Before the owned validation checkout is cleaned, the controller authenticates containment, raw-byte size bounds, receipt/PNG digests and the observed candidate digest against the exact result tree, then retains complete bytes in ContentStore with command and tree provenance. Review transports attach those authenticated pixels directly to the existing configured provider input; they add no tools, browser or network permissions. Unsupported transports refuse before dispatch. Final Objective review prefers its own fresh validation images. When none are supplied for a selector, it may inspect retained accepted Work Item pixels only if their original exact result tree equals the final tree and completion, command, artifact and integration bindings remain verified. Their original Work Item provenance stays explicit; they are never relabeled as a fresh final execution, and earlier verdicts do not determine Objective acceptance. Different-tree images supply no current observation. Selection is part of the configuration digest, so changed selectors require a fresh correctly bound Objective. Compile and graph review receive the configured selectors as structured input, so a plan can route runtime-evidence proof through the exact selector command; selectors grant no command authority.

The canonical review packet carries complete bytes, digests, provenance and completeness flags. State keeps a packet by reference: each row's identity, provenance, digest and completeness, never its bytes. A retained packet is replayed by re-deriving its rows (pinned sources from Git at the base, controller records from state) and checking each digest. When the reviewer has an exported read-only evidence workspace, rendered bodies over 2,048 bytes use authenticated files in its existing root: pinned authority/source bodies under `pinned/`, controller records under `evidence/`, and exact current-tree files separately under `candidate/`. Result and final review roots also hold the review base's copy of every changed path under `base/` and each changed path's complete patch under `changes/`, listed in `changes/INDEX.json`, so a reviewer compares base and result itself instead of relying on budgeted inline excerpts. Small records can remain inline; calls without exported files retain inline delivery. This threshold changes delivery, not evidence completeness or the finding schema. Reviewers may inspect ranges or structured keys and explain the file/range supporting a finding, while citing the existing packet-local evidence index. A descriptor proves availability and identity; it does not establish that a criterion passed.

Compilation derives material risks from the Objective's flows and planned architecture and assigns their proof responsibility without adding acceptance requirements or prescribing an implementation. Item review investigates its contract and those risks in current source; the source map supplies leads without restricting relevant discovery. It judges the item's acceptance and then, verbatim, every Objective criterion and source obligation the coverage says its review proves (semantic coverage, plus final-review coverage when the item is the whole graph), with the same verification standard final review applies, so a gap is refused and repaired before delivery. Final review checks every original criterion on the integrated source, concentrating investigation on current interactions and unmet proof obligations rather than treating earlier verdicts as acceptance. When pending asynchronous work can outlive selection or navigation, trace whether success, error and cleanup completions still belong to the current intent. Distinguish static source proof from runtime ordering/state-transition coverage; passing happy-path checks do not prove unexercised orderings.

Successful Work Item review retains bounded complete literal evidence actually cited by its findings in the existing validation snapshot, each body by ContentStore reference. Final review can retrieve those findings, designs and bodies through the evidence map with their original references and exact result/candidate tree relationship. Sharing identical evidence bytes with matching provenance avoids duplicate delivery; prior verdicts remain advisory. A result already at the final tree supplies exact path, mode, blob and ownership descriptors without repeating its patch text. Original source references retain their pinned-source meaning. Verified source bodies and command receipts may be reused only within their authenticated scope; missing legacy or bounded-out bodies require ordinary source/evidence reads. Compilation may settle useful shared interfaces and state ownership within the Objective's constraints so independent components can proceed without repeatedly inventing their contract.

An accepted human planning answer retains its original question, answer, actor, reason, time and graph/packet/review binding in the active continuation. The shared derived worker brief and Work Item/final review observations supply that same verified context for CLI answers. It resolves the named choice within the Objective; it does not change the immutable graph, grant source or command authority, or prove that the app implemented the choice. Review observations use the existing literal controller-evidence grounding path. Historical absent context stays unavailable.

## State and recovery

Each Objective has one atomic local continuation snapshot outside the target repository. An exclusive verified owner controls mutations; resource and configuration identities bind operations to the run. Diagnostics and optional captures observe the run and retain actual available usage, but never reconstruct or control lifecycle state.

The sequential background queue freezes an optional whole elapsed deadline in its acknowledged Git owner claim before first dispatch. Restart and re-enqueue reuse that exact binding, including an explicit uncapped admission; configuration changes apply only to fresh Objectives. Refusing an unprojected plan records the refusal on that run's settled claims, so the next run plans afresh under a new claim and deadline. Human wait and unavailable-host time count toward the deadline. The existing runner owns expiry and resource cancellation, and an expired admission without continuation cannot start provider work.

GitHub progress comments, on by default, project validated continuation state into one Live status comment per Objective and started Work Item issue, edited in place, plus new comments only for notifications: a needed decision, the Objective's outcome, or a failed or waiting Work Item. Timestamps alone never trigger a notification. Notification identity and request accounting live in the same atomic continuation: immutable snapshot identity, exact body and digest, authenticated numeric actor ID, observation time and the observed comment identity and publication time. At most 64 notification requests are retained per Objective, and 64 per Work Item recorded with the item's issue in `workItemTracking`, so a later graph revision cannot rebind its history; history and unresolved intents are never evicted. The sole creation intent is recorded before dispatch. A lost response remains unknown: restart may only reconcile one matching Factory-authored comment at the exact repository, Objective, marker and body. An empty or ambiguous lookup never authorizes another create, and unresolved publication holds further notifications on that issue. Notification comments are never edited. Exhausted history and unavailable or unknown publication stay visible in local status as degraded tracking, independently of app acceptance. These comments supply observations and links, not lifecycle authority. The disclosure settings are in the [user guide](USER-GUIDE.md#github-progress-check-ins).

Factory reads no human comment as input. Decisions, amendments, retry, repair, cancellation and the other lifecycle operations go through the local harness commands.

Optional Project projection updates only an existing Objective card's explicitly Factory-managed Status field. Verified state determines its configured option; accepted status requires actual accepted Objective closure. A retained prewrite intent permits one mutation, with an original returned response distinguished from later read-only observations. An uncertain submitted write fences later writes to that field; a proven not-sent attempt retains its accounting without creating submission uncertainty. Projection failures do not become app acceptance or authorize recovery.

Prospective controller diagnostics identify each observer session and each formal step body or diagnostic span attempt. Pending polls settle a body attempt without claiming phase success; invalid answers, semantic review refusals and lost workers remain observations even if a later attempt succeeds. Actual readiness command failures bind their enclosing formal attempt; worker readiness and stopped-worker observations retain the original worker identity. Session start and closure bind the configuration and observer source bytes, with monotonic sequence and write/loss counters. The read-only formal-history summary requires a closed, continuous session and paired attempt terminals. A missing closure, write failure, observation after closure or unmatched attempt makes completeness unknown. Supported controller handoff settles its formal controller attempt as paused with `controllerDisposition: handed-off` and closes the observer session with lifecycle `handed-off`, without a fault class. The Objective remains unaccepted; ordinary errors and earlier failure observations remain failed. These receipts describe observed history, not acceptance, permission to retry, billing completeness or resource cessation. Existing logs without these fields remain unknown; no operational snapshot migration or historical backfill is performed.

Resume from supported recorded state. Preserve accepted results, rejected responses, artifacts, failures, usage and spent allowances. A terminal run remains terminal. Never manually edit state, introduce a new root to evade a fence, or replay an external mutation whose outcome is unknown.

Pause, drain, handoff and cancellation follow owned-process and safe-point rules. An aborted execution pass settles its owned work, then leaves cancellation finalization to the controller outside the pass's aborted process scope. The controller closes cancelled Work Item issues, releases settled agent sessions and records terminal cancellation only after those operations succeed; during execution, a planning turn whose adapter settled its local process without a native outcome becomes unavailable before that disposal; genuine unresolved cancellation remains a fence. A declared planning dispatch hook records diagnosis submission after complete attempt admission and acknowledges that intent before transport. Permanent unaccepted cancellation may retain an unknown diagnosis response after authenticating the exact current atomic snapshot under its exclusive owner lock and disposing every owned native scope. It preserves the submitted intent, history and usage; ordinary resume and restoration remain fenced. Primary planning uses the same post-admission dispatch checkpoint. For a supported retained-planner scope, permanent cancellation may retain an unknown primary invocation after its native-before-effect checkpoint coverage is authenticated and every recorded native scope is disposed. The existing planning record retains the exact invocation/scope/adapter resource proof; an empty set is covered by that producer invariant, never by process, file or diagnostic absence. Fresh graph review and unresolved restored scopes cannot use this proof. Project claim settlement authenticates complete admission receipts, including compound field updates. Before replacement work, verify the predecessor is terminal where required and that its owned controllers, workers and resources have ceased. An explicit operator decline can dispose an unadmitted in-scope worker discovery while its Objective is paused or stopped and owned resources are settled. The atomic WorkState retains the original proposal and a run/item/attempt/result/graph/digest-bound actor/reason decision. Dispatch and terminal eligibility recognize this disposition; result and final review expose it as operator provenance, never an accepted amendment or acceptance proof. It changes no graph, ownership, provider allowance or result acceptance. For a current source-host worker, a ready receipt without a planner current-turn record is settled only when its adapter-recorded native EOF and owned-worker settlement match the exact collected result, execution identity and retained worker handle. Foreign/restored ownership retains its strict portable proof; missing, changed or unknown receipts remain fenced. Retry, repair and graph amendment use their supported lifecycle operations and recorded finite limits; there is no implicit extra attempt or provider fallback.

Final acceptance checks graph coverage, the integrated candidate and the current remote head before atomic sealing and closure. Publication and integration preserve exact commit/tree/head checks and target branch protection. A changed head is observed and validated through the supported path, never silently accepted.

See [stopping and recovery](USER-GUIDE.md#stopping-and-recovery) for the operator commands. Their implementation and status output are the authority for the next supported action.

### Git durability boundary

The existing atomic snapshot remains the lifecycle authority. Synchronous local saves mark checkpoint data dirty; awaited effect admission publishes the exact intent and charged allowances before external dispatch. A separate transport receipt records the observed archive base, attempted candidate, independently verified acknowledgement and pending loss window. It supplies durability facts, not a second queue, scheduler or external-effect outcome.
