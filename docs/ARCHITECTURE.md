# Factory architecture

Factory turns an approved Objective in a target repository into a reviewed Work Item graph, exact-tree results and guarded GitHub delivery. It is a plugin and CLI, not a hosted service. Never execute it against its own source repository.

This is a conceptual map. Update it when subsystem ownership or the lifecycle changes, not for ordinary fixes. Exact interfaces and validation rules live in the code; commands and recovery instructions live in the [user guide](USER-GUIDE.md).

## Delivery flow

```text
Objective + pinned sources → compile and review → project Work Item graph
  → schedule → execute → validate exact tree → review acceptance
  → deliver → validate integrated result → seal acceptance → close Objective
```

The target owns requirements, validation commands, permissions, protection rules and acceptance. Factory coordinates that work under the approved configuration and recorded limits; it never grants itself deployment, provider, retry or spending authority.

## Planning and evidence

Pin the Objective, default-branch commit and complete cited source contents. Models select semantic choices; code derives canonical identities, hashes, command text and relationships. Providers share the same grounding and validation rules.

Compilation plans a useful execution DAG rather than minimizing item count. Substantial independently implementable and verifiable components become first-class Work Items with disjoint ownership and settled shared contracts; dependency edges name actual required outputs, not shared decisions or a later combined check. Each feature owner completes its relevant implementation, tests and documentation with acceptance and real proof achievable at its own stage. Shared files have one responsible owner. Full end-to-end obligations normally use authorized integrated validation and one independent final Objective review; final-review coverage may belong to an implementation item without claiming an early pass. Feature owners can author combined checks against settled interfaces, while sibling-dependent execution waits for integration. A downstream implementation item needs an identified deliverable that actually consumes completed peer outputs. Read-only QA supplies named required evidence or material-risk proof absent from final validation/review, including source-required late named CI, rather than duplicating final checks. Required runtime layers, orderings, negative controls and complete evidence remain mandatory. Aggregate children express hierarchy with explicit dependencies. Compiler output contains a short sufficient contract without repeating source bodies or other fields, never truncating required facts. Small cohesive changes remain one item when splitting would not improve the useful critical path; graph review needs concrete grounds to flag avoidable serialization.

Work Item repair distinguishes an actual failed-command capture from an explicitly produced semantic acceptance refusal. The existing recovery failure retains the rejected finding or operator decision against its exact tree and criterion, bound to separately retained passing validation receipts. Diagnosis must ground an owned correction in that refusal and complete candidate contents. Missing failed commands do not select the semantic path; unknown evidence remains stopped. Both paths preserve the original attempt and finite repair charge. For a self-contained model refusal after passing validation, diagnosis may omit historical worker input bodies and unrelated pinned source bodies only after authenticating the retained refusal, command authority and complete owned current files against the exact candidate tree. It delivers the original failure and validation, complete owned candidate bodies, relevant authority sources and indexed omission identities inline; tool-free diagnosis does not resolve worker substring selectors. Missing mappings, prerequisites, dependency context or current file evidence use the complete request. Canonical graph inputs, repair evidence, indices, digests and readiness remain unchanged; an omitted body cannot ground actionable repair. Quiet structured-response timeouts surface a retained decision on the first call rather than automatically replaying the unchanged prompt; bounded capacity retries and the existing inactivity limits remain unchanged.

Commands need exact source or verified base authority. Ownership is literal and enforced. Existing acceptance scripts and package-manager/security metadata retain their fixed constraints unless the Objective explicitly authorizes the supported change. Review cannot invent prerequisites, repair quotes into evidence or approve missing facts.

Readiness coverage selects an exact probe and, when supplied sources require it, ordered prerequisite validation rows before that probe. Preparation is authenticated separately in every fresh preflight, worker and final validator checkout; ignored installs and historical receipts do not transfer. The local worker uses the shared validator executor before its provider starts, and drivers unable to authenticate their actual environment refuse such work. Preparation receipts never replace semantic acceptance.

Validation runs the approved commands against the exact candidate tree and records its identity and outcomes. Acceptance review evaluates that same tree using authenticated receipts, complete required source evidence and declared criteria. Missing, incomplete or invalid evidence stays missing, incomplete or invalid; passing unrelated checks does not replace it.

Compilation derives material risks from the Objective's flows and planned architecture and assigns their proof responsibility without adding acceptance requirements or prescribing an implementation. Item review traces those risks in complete current source; final review checks the original criteria on the integrated source, not earlier verdicts. When pending asynchronous work can outlive selection or navigation, trace whether success, error and cleanup completions still belong to the current intent. Distinguish static source proof from runtime ordering/state-transition coverage; passing happy-path checks do not prove unexercised orderings.

Successful Work Item review retains bounded complete literal evidence actually cited by its findings in the existing validation snapshot. Final review supplies those findings and bodies with their original references and exact result/candidate tree relationship, sharing only identical evidence bytes with matching provenance. Within the existing evidence budget, complete accepted designs come first, followed by cited evidence from results matching the final candidate tree, before historical delta text. A result already at the final tree supplies exact path, mode, blob and ownership descriptors without repeating its patch text. Original source references retain their pinned-source meaning. Missing legacy or bounded-out bodies require ordinary source/evidence reads, and prior verdicts never become final acceptance. Compilation may settle useful shared interfaces and state ownership within the Objective's constraints so independent components can proceed without repeatedly inventing their contract.

An accepted human planning answer retains its original question, answer, actor, reason, time and graph/packet/review binding in the active continuation. The shared derived worker brief and Work Item/final review observations supply that same verified context for both CLI and GitHub answers. It resolves the named choice within the Objective; it does not change the immutable graph, grant source or command authority, or prove that the app implemented the choice. Review observations use the existing literal controller-evidence grounding path. Historical absent context stays unavailable.

## State and recovery

Each Objective has one atomic local continuation snapshot outside the target repository. An exclusive verified owner controls mutations; resource and configuration identities bind operations to the run. Diagnostics and optional captures observe the run and retain actual available usage, but never reconstruct or control lifecycle state.

The sequential background queue can freeze an optional whole elapsed deadline in its existing intake authorization before first dispatch. Restart and re-enqueue reuse that exact binding, including an explicit uncapped admission; configuration changes apply only to fresh Objectives. Human wait and unavailable-host time count toward the deadline. The existing runner owns expiry and resource cancellation, and an expired admission without continuation cannot start provider work.

Optional GitHub progress comments project validated continuation state into bounded, append-only snapshots. Meaningful changes are coalesced; timestamps alone never trigger publication. Exact creation intent is retained before the sole dispatch, and an uncertain response permits only read-only matching reconciliation. Publication failure degrades tracking independently of app acceptance. These comments supply observations and links, not lifecycle authority. See the explicit disclosure and decision contracts in [GitHub management](GITHUB-MANAGEMENT.md).

An independently enabled remote decision channel accepts one exactly bound, acceptable pending planning question from an explicitly allowlisted human GitHub account. It authenticates the comment node, literal body, author and edit metadata, then rechecks current plan, ownership, control mode and deadline before atomic consumption. A passive question hold preserves the existing controller; deliberate pause/drain and unresolved effects cannot be cleared by a comment. Remote result acceptance, refusal, retry, repair, cancellation, merges and limit changes remain outside that channel.

Optional Project projection updates only an existing Objective card's explicitly Factory-managed Status field. Verified state determines its configured option; accepted status requires actual accepted Objective closure. A retained prewrite intent permits one mutation, with an original returned response distinguished from later read-only observations. An uncertain submitted write fences later writes to that field; a proven not-sent attempt retains its accounting without creating submission uncertainty. Projection failures do not become app acceptance or authorize recovery.

Prospective controller diagnostics identify each observer session and each formal step body or diagnostic span attempt. Pending polls settle a body attempt without claiming phase success; invalid answers, semantic review refusals and lost workers remain observations even if a later attempt succeeds. Actual readiness command failures bind their enclosing formal attempt; worker readiness and stopped-worker observations retain the original worker identity. Session start and closure bind the configuration and observer source bytes, with monotonic sequence and write/loss counters. The read-only formal-history summary requires a closed, continuous session and paired attempt terminals. A missing closure, write failure, observation after closure or unmatched attempt makes completeness unknown. Supported controller handoff settles its formal controller attempt as paused with `controllerDisposition: handed-off` and closes the observer session with lifecycle `handed-off`, without a fault class. The Objective remains unaccepted; ordinary errors and earlier failure observations remain failed. These receipts describe observed history, not acceptance, permission to retry, billing completeness or resource cessation. Existing logs without these fields remain unknown; no operational snapshot migration or historical backfill is performed.

Resume from supported recorded state. Preserve accepted results, rejected responses, artifacts, failures, usage and spent allowances. A terminal run remains terminal. Never manually edit state, introduce a new root to evade a fence, or replay an external mutation whose outcome is unknown.

Pause, drain, handoff and cancellation follow owned-process and safe-point rules. An aborted execution pass settles its owned work, then leaves cancellation finalization to the controller outside the pass's aborted process scope. The controller closes cancelled Work Item issues, releases settled agent sessions and records terminal cancellation only after those operations succeed; genuine unresolved cancellation remains a fence. Before replacement work, verify the predecessor is terminal where required and that its owned controllers, workers and resources have ceased. Retry, repair and graph amendment use their supported lifecycle operations and recorded finite limits; there is no implicit extra attempt or provider fallback.

Final acceptance checks graph coverage, the integrated candidate and the current remote head before atomic sealing and closure. Publication and integration preserve exact commit/tree/head checks and target branch protection. A changed head is observed and validated through the supported path, never silently accepted.

See [stopping and recovery](USER-GUIDE.md#stopping-and-recovery) for the operator commands. Their implementation and status output are the authority for the next supported action.

## Execution, isolation and media

Local workers operate in owned worktrees with private credential-free scratch homes and the configured network/secret policy. Toolchain visibility, commands and writes remain bounded by the approved attempt and ownership. Provider-specific APIs and credentials stay inside their adapters and outside target repositories.

### Conversation continuity and Objective knowledge

Conversation continuity is an optional role-scoped capability at AgentHarness, ExecutionDriver and PlanningModel/PlanningTransport, declared through `sessionCapabilities.resumeRoles`. Factory owns repository, Objective/run, configuration and role bindings and allocates logical session identities. Implementation and result-review sessions also bind the graph and Work Item; Objective-review sessions bind the graph. A planner's immutable input binding survives graph revisions, while each turn binds the current graph and request. Adapters own opaque native references, private storage, current workspace/permission rebinding, accounting and disposal. Receipts persist in the existing atomic snapshot; superseded receipts remain historical. Ready, in-flight, unavailable and released distinguish usable context, unresolved work, unusable context and completed disposal. A native thread is never an acceptance or permission receipt.

The planner can continue from preparation through compilation, correction, diagnosis and graph amendment. Its turns are serialized and explicitly bounded; graph review starts an independent fresh conversation. Implementation, result review and Objective review remain separate roles. Each review receives complete authoritative evidence for the current candidate. Previous paths, findings and packet-local indices remain historical until current facts establish their applicability. Native agent loops, compaction and working-context management remain the harness's responsibility; continuity adds no attempt allowance or permission.

Local Codex and Claude support planning and independent result/Objective-review continuity. Codex and Claude support implementation continuity; Claude workers with user settings remain fresh. Copilot and managed execution stay fresh across attempts. Copilot continuation is implemented but disabled pending live account, restart, workspace and accounting qualification. Codex structured tool-free compilation, graph review and diagnosis use `planning.codex.transport`, defaulting to `exec`. Opt-in `app-server` uses an owned stdio client and private native storage; tree result/Objective reviews are explicitly routed to exec with their candidate-only offline permission profile, and SDK workers are unchanged. Routing is selected before dispatch, never as fallback after a transport error. Upstream labels app-server experimental and unsupported for production; see the [user guide](USER-GUIDE.md#retained-conversations).

Before dispatch, the existing snapshot records the bounded turn's invocation, request and evidence identities, plus its optional immutable neutral `deadlineAt`. Structured planning admits one elapsed ceiling before capacity backoff, taking the earliest of its configured/default fifteen-minute budget, the current admission scope's Objective deadline and any retained same-turn deadline. Codex exec/app-server and Claude map that shared ceiling into `ProviderTurnGuard` alongside their existing inactivity limits. Progress cannot renew elapsed time. Expired admission is checked before native dispatch, including after asynchronous startup; local worker limits are unchanged. Older receipts without the field remain valid historical state, and unfinished old turns remain fenced rather than acquiring a deadline through replay. Submitted or uncertain turns cannot automatically replay. Adapter reconciliation may establish active, unknown or settled work; recovered exact final bytes still pass ordinary decoding and grounding against the current request. Diagnostics, process absence and transcript inspection cannot manufacture a settled receipt. Disposal follows owned resource cessation through the adapter, preserving accounting and result artifacts. Elapsed expiry requests cancellation but supplies no native terminal fact: a submitted turn without one stays in-flight even when its local resources settle. Reconciliation retains its separate bounded read/cleanup window and cannot renew the original generation budget.

All worker adapters share optional private advisory handoffs through `.factory-handoff.json`. Common collection excludes this staging file from Git delivery and attaches actual committed source bytes and producer identities. The controller retains immutable records and supplies relevant settled ancestor notes or cross-branch leads at dispatch, including whether referenced bytes are present unchanged in the execution base. Hypotheses and interface claims stay advisory. Required inputs and human decisions keep their original authority; a prior result or summary cannot prove current acceptance. Knowledge uses the existing content store and continuation snapshot, with no separate orchestration or memory service. Raw native conversations remain inside their adapters.

Codex and Claude resumed counters can be thread-cumulative. A resumed invocation authenticates its prior boundary and records category-wise deltas only where both snapshots support them; missing or reset categories stay unknown. Raw cumulative totals remain alternate receipts. Copilot preserves native counters without assuming that its input counter includes cache categories. References to a retained child without an authenticated new-turn boundary mark child accounting unavailable and parent coverage partial. Telemetry records fresh/resumed mode and logical turn without interpreting native thread identifiers. Cache analysis separates known cached input divided by all observed input from the paired subset with both categories available; neither proves complete accounting or billed savings.

Regular pull requests and native linear stacks share exact validation and guarded delivery. Media selection binds a complete approved asset set by identity; content storage and LFS preserve bytes through materialization, hydration, validation and delivery. Neither a file manifest nor a historical receipt proves that current runtime resources were hydrated.

New runs admit `exact-request-v1` publication. The existing atomic snapshot retains up to 64 request intents per Work Item, separate from replaceable attempt state. Immediately before the sole PR create dispatch, the exclusive owner saves repository/run/configuration/item/attempt, branch/base, exact head/tree and literal title/body digests. That intent means possibly submitted, including a crash before dispatch; only the same invocation receives the ephemeral one-shot create permission. A persisted unresolved intent permits read-only exact PR reconciliation, with no branch/LFS push or repeated POST. Empty reads, errors, elapsed time and restart cannot clear it. Positive observations bind authenticated repository/base/head and literal PR metadata while preserving the original submission uncertainty. Existing PRs found without creation retain their actual observed metadata separately from desired new descriptions. Known closed-PR operator retry can retire only its recorded observed identity; history is never evicted, and a full history fails closed before new effects. Legacy unpublished delivery without admission remains unrecorded/unknown and cannot publish. Diagnostics do not upgrade it, and no override or abandonment authority is introduced.

Managed execution uses the same contracts but remains separate from claims of live provider acceptance. Configuration and source declarations alone do not qualify an external integration.

## Checks and releases

CI builds Factory and runs a small real integration suite over Git, processes, disk, scanner and the offline packed CLI. It uses no fake providers or model responses. Real provider/GitHub acceptance belongs to the approved milestone's substantive outcomes.

The [release procedure](RELEASING.md) verifies synchronized versions, exact artifacts and provenance, and protects immutable release tags. Issues, pull requests, Git history and GitHub release notes record changes; this file is not a fix log.
