# Installed finding-reporting qualification

This gate qualifies the optional issue-publication path from an exact installed Factory artifact.
It is intentionally not run by ordinary unit tests or by a source checkout. The operator must grant
separate authority naming one disposable source Objective, every target repository, public/private
audience, maximum publication writes, and cleanup/retention expectations. Credentials alone are not
authority. Do not use a real vulnerability; security findings remain outside the ordinary path.

Bind retained evidence to the source commit, release-manifest digest, installed bundle digest, run
and policy digests, Objective/Work Item/attempt, finding ID, report digest, target repository, and
target issue node/number. Sanitize evidence; never retain credentials, raw prompts/logs, personal
data, machine paths, or private topology.

The disposable scenario must prove all of the following:

1. A safe, ordinary validation finding creates exactly one issue in an explicitly allowed target.
   Its body separates expected behavior, observation, reproduction, impact, classification, and an
   explicitly unverified possible cause, and carries the exact machine marker.
2. Repeating the same observation links the existing issue without another mutation. Concurrent
   sibling observations with proven common-cause evidence do not fan out into an issue storm.
3. Inject response loss after the target commits issue creation, restart the installed Supervisor,
   and prove exact-marker reconciliation records the same node without a second create. Inject an
   ambiguous no-observation outcome and prove Factory does not redispatch.
4. A recurrence bound to a different artifact has a different finding identity. A closed prior issue
   is not reopened automatically and does not erase the distinct recurrence.
5. Exhausted allowance, permission denial, disabled Issues, required templates, rate/circuit
   refusal, and unavailable destinations settle to bounded issue-ready/refused/limit dispositions
   without consuming attempts or changing graph, model-token, session, network, or spend authority.
6. Public/private audience mismatch, secret-like content, private paths/topology, personal data,
   raw logs/prompts, and unverified security reports are rejected before target publication.
7. An Objective blocker prevents false successful completion while unrelated independently valid
   work continues. Every durable candidate reaches a disposition before the run becomes terminal.
8. `factory_status`, `factory_explain`, restart recovery, and authenticated event replay reconstruct
   the same six final dispositions and exact issue identity.

Use a transport double for deterministic prepublication fault injection and separately exercise the
authorized live GitHub boundary for the exact installed artifact. Never infer a pass from source
tests, a staged bundle, title search, or a locally acknowledged request.
