# Installed public autonomy qualification

This contributor procedure supplies the ordinary installed scenario for [#253](https://github.com/clockgrove/factory/issues/253).
It is not a plugin user tutorial or evidence that the scenario has passed. Follow
[the public release procedure](PUBLIC-RELEASE.md) for exact artifact gates. The
finite compounded-failure matrix belongs to #254, separately from this scenario.

## Candidate and run record

Freeze one reviewed candidate containing #246, #249, #250, #251 and #252, then
build and install that exact artifact. Before creating the remote or using models,
record its source commit, tree, package SHA-256, installed location, owner, host,
intended service environment, public source inventory, repository name, delivery
strategy and provider/model identities. Record actual existing spending limits;
unknown historical usage is not zero. If unknown accounting prevents enforcement
of a binding limit, resolve that before calls.

For this scenario record two authorized Objectives; concurrency two; one installed
scenario attempt; one coordinator restart; no implementation repairs; one
validation-environment result repair; and planning-revision capacity sufficient
for the one required discovery plus any separately authorized planning correction.
Use explicit numbers in the actual authority and per-path repair policy; do not
copy an unspecified allowance from this prose. No automatic replacement run is
implied. A failed run stops for diagnosis; preserve it before proposing a bounded
corrected successor. Existing explicit budget and provider limits remain binding.

Before remote creation, run this local mechanical fixture check:

```sh

node test/autonomy-fixture-preflight.mjs
```

It uses the real compiler to verify literal final commands and complete pinned
source contents for the initial and accepted-predecessor baselines. It also proves
checks fail the unfinished baseline and pass a small complete implementation,
including rejection of an input-mutating result that passes the ordinary join. It invokes no
Factory models and proves no runtime behavior. Existing focused regression suites
own negative admission cases: out-of-scope discovery, stale graph, exhausted
allowances, absent required environment, accounting uncertainty under a binding
cap, and ambiguous effects. Record the exact candidate's passing test identities;
do not manufacture those failures in the ordinary live scenario.

The target's `source-check` workflow is a syntax check, not product acceptance.
Configure the exact target's protected integration and required check only under
explicit security-control approval. Record the effective rule and authenticated
check identity; do not infer protection from the workflow file. Factory's local

## Installed flow

Use packaged setup to bind the target with local execution, native-stack delivery,
concurrency two and the intended Codex environment. Run the installed `readiness`
command with an existing disposable outside directory from the **same launch
context and environment that the user service will use**. Record successful shell
execution, workspace write and outside-write refusal. An earlier source probe or
a service lifecycle test under another CODEX_HOME does not establish readiness.
Do not alter login persistence or security settings to make the probe pass.

Use the installed intake surface from #252 to enqueue the finite authority file,
then install/start the supervisor in intake mode. Verify exact help and integrated
command semantics before execution. Enqueueing binds both bodies; predecessor
acceptance controls when the second plan is materialized. Do not plan the second
against the original empty baseline or manually launch it to simulate intake.

Inspect the rendered worker and independent reviewer packets before paid execution:
all original obligations, immutable source contents, literal commands, criterion
IDs and evidence selectors must be present at the phase that uses them. Capture
private prompts only in the configured private capture destination. The initial
plan must contain independent alpha/beta leaves and the explicit summary join;
it must preserve the inspection requirement without pre-creating the discovered
QA node. If planning cannot represent this contract, diagnose it before activation
rather than weaken the scenario or edit the accepted graph by hand.

Observe both workers genuinely active before either completes. Record attempts,
start/completion times and harness identities; a concurrency setting or two
planned nodes is insufficient. The alpha result proposes required QA. Verify an
independently reviewed successor graph, unchanged started identities, a newly
projected QA child/aggregate hierarchy and explicit join dependencies.

After a known identifiable worker has started, request one supported supervisor
restart. Preserve before/after run, attempt, model-session, issue and PR identities.
The coordinator must reconcile the same work, not silently issue another provider
submission. If the installed lifecycle cannot restart at that boundary, stop and
report the unsupported transition; do not kill blindly or rewrite continuation
state. Observe operation from a separate session after the launching CLI exits.

When beta's environment probe fails, preserve the failure digest and exact result
commit/tree, then supply the restored prerequisite and the #250 supported repair
proposal with concrete diagnosis, correction, actor, failure digest and tree.
The bound policy must permit this class with one result rereview and zero
implementation repairs. Check that Factory consumes that allowance, revalidates
the preserved candidate and independently reviews it before delivery. No manual
acceptance, implementation retry, state editing or allowance reset is permitted.
This proves a diagnosed validation-environment repair with an externally supplied
correction; it does not prove autonomous implementation repair.

Allow the first Objective to reach exact current-graph acceptance and only then
the second to start from the accepted predecessor. Do not treat completed leaf
PRs or a successful final review alone as terminal acceptance.

| Accounting and retirement                  | Available usage with unknowns explicit, stopped owned resources, retained/deleted fixture disposition                            |

An independent reviewer checks the complete record against this map. Keep raw
prompts, local run identifiers and logs in their authorized evidence destination;
publish a concise sanitized result with exact public artifact/commit identities.
Mark each claim implemented, integrated, installed or qualified according to what
actually ran. No earlier artifact's live result transfers to this candidate.

Finish every success, failure or cancellation with resource disposition and fixture
retirement: delete only under applicable explicit authority, otherwise retain with
reason, owner and an acceptance/disposal review trigger. Preserve failures and
unknown accounting. Public acceptance precedes any separately authorized adopter
run; this procedure grants no private target authority.
