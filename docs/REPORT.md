# The cost report

`pendulum report` reads what Pendulum's own records say about a period or a set of Objectives and prints every figure already computed: as JSON with `--json` (the schema below), else as plain Markdown for a terminal or CI. Pendulum is only the data layer. Your coding agent presents the JSON however you ask (a table, a chart, an HTML page, a document) through the [`/pendulum:pendulum-report`](../plugin/skills/pendulum-report/SKILL.md) skill, and it never adds, averages or derives a dollar figure itself.

```sh
pendulum report [--since DATE] [--until DATE] [--issue N[,N...] | --label NAME | --parent N | --compare A,B | --compare-label A --compare-label B] [--json] [--max-calls N] [--by account] [--app ID] [--self LOGIN]... [--repo OWNER/NAME]
```

- **Scope.** `--since` and `--until` (a date, or a time with its zone; `--until` is exclusive) give a period: every Objective with a stage that started in it. `--issue`, `--label` and `--parent` (the parent issue's sub-issues) give a set of Objectives, read whole unless a period is given too. `--compare` and `--compare-label` give two sets, the arms of an experiment, side by side (Compare two arms, below). A period with no `--since` (and no set) starts 30 days before `--until`, or before now, at that day's UTC midnight (`scope.defaultPeriod`). A decision-spend line, which records one UTC day's decision calls, counts when that day's start (its midnight) falls in the period.
- **Reads.** The issue comments hold every marker the report needs: the progress, harness, spend, ledger, vendor, decision-spend and finish markers. For `--issue`, each named issue's own comments are read; otherwise one paged repository-wide read (`issues/comments?since=`). The Objectives' issues and the PRs on their `pendulum/<n>` branches give each one's outcome (for `--issue`, each branch's own PRs). A stage's per-pass ledger, tokens, Pendulum release and (when its harness line names none, as Copilot's at its default model) model come from the ledger line beside its spend line (below), with no artifact read. Usage artifacts are listed and read only for the stages whose comment does not say everything: a stage with no spend line, for its dollars, and a stage with no ledger line (a stage from before it, or one whose ledger did not fit) whose ledger no local record in this clone holds, for those figures. A stage with a spend line keeps that line's dollars, so none is counted twice: its ledger, from its comment or its usage record, gives its passes and tokens, never its total. The Objectives with a stage that has no spend line are read first, so a call budget that runs out costs per-pass detail before a dollar figure. A record that names a stage comment the report does not attribute to Pendulum is that stage's: it adds no stage and no dollars. Artifacts uploaded before the period began are not read. An artifact a fork's run uploaded (its workflow run's head repository is not the repository), or one that names no repository id, is never read, whatever its name: it is counted as `artifact-foreign`. Each artifact read is downloaded with `gh run download`, which reads its run's artifact list, and kept by its artifact id under your cache directory (`$XDG_CACHE_HOME`, else `~/.cache`; `~/Library/Caches` on macOS), in `pendulum/artifacts/<API host>/<owner>/<name>/`, with only the fields the report reads, never in the repository, so a later report downloads it no more. Local mode's own records under `<clone>/.pendulum/<n>/` are read for the per-pass ledger when the command runs in the clone. No job or list of workflow runs is read, and no timeline but those a labelled set needs (Who applied the label, below); nothing is written.
- **Budget.** The command prints its planned GitHub API calls to stderr before it reads: a paged read's first page, then, from that page's `Link` header, the pages left (said as "at least" where GitHub names no last page); for `--issue`, each issue's comment pages from its comment count; for a label whose applier is checked, each listed issue's timeline and, as each one is first met, a labeller's permission; after an Objective's artifact lists, the downloads its artifacts not yet cached take, two each. It stops at `--max-calls` (300 by default). A stopped report still prints what was read, with `source.complete` false, and exits 3: an Objective whose PRs were not read has no outcome (null) unless a state label or an open issue decides it, and a stage whose usage record was not reached is of unknown cost for `stopped`.
- **Token.** Local mode's token for the repository when it is saved, else your `gh` login: the report shows only what that login can read.
- **Trust.** A marker counts only from Pendulum's own login (the token's), a login `--self` names (each one, exactly, and only on a comment by someone who can push), or Pendulum's App. The App's numeric id comes from `--app`, else the repository variable `PENDULUM_APP_ID` (one call; `pendulum setup` writes it beside the secret of that name), else `PENDULUM_LOCAL_APP_ID`. A stage comment by anyone else who can push, or through another GitHub App, is a stage of unknown cost (`unattributed`), never its figures; its vendor comment adds nothing to it, one with no progress comment is a run of unknown cost but no stage, and its decision-spend lines are decision calls of unknown cost. Anyone else's, `github-actions[bot]` included, counts nothing. `source.trusted` lists the logins and the App the report trusted. For an install from before the variable, save it once: `gh variable set PENDULUM_APP_ID --repo OWNER/NAME --body <the App's numeric id>` (doctor names the same line on GitHub Actions when it is missing or names another App).

## Compare two arms

Tag the Objectives of each arm of an experiment (a model, an effort, a setting) with an experiment label, `pendulum:experiment:<name>` ([USAGE.md](USAGE.md), Run an experiment), then put the two arms side by side:

```sh
pendulum report --compare sonnet,opus          # pendulum:experiment:sonnet against pendulum:experiment:opus
pendulum report --compare-label wave-6 --compare-label wave-7   # any two labels
```

- **Arms.** `--compare` takes two experiment names (the part after `pendulum:experiment:`), joined by a comma or as the flag twice; `--compare-label` takes two label names. Each arm is every issue with its label, read whole: `--since` and `--until` are refused with them, since a period would cut a merged Objective's dollars to the stages in it. An issue both arms count for is in neither, listed in `comparison.inBoth`.
- **Who applied the label.** An arm's label counts for an issue only when the person who last applied it, by the issue's timeline, can push or is a maintainer the workflow names, as for the harness and model labels: a label applied by anyone else, by a bot or through an App is not counted (`untrusted`, missing code `label-untrusted`), nor one whose labeller's permission the token may not read (a 403: `unverifiable`, missing code `label-unverifiable`). An issue both arms list counts only once each arm's check of it ended. A `--label` that is an experiment label follows the same rule. The check reads each listed issue's timeline once, and each labeller's permission once, before any other record of it; the other labels a `--label` names are read as GitHub has them.
- **Per arm:** n (its Objectives) and their outcomes; then, over its merged Objectives, the median and p25..p75 of the dollars per merged Objective of each billing kind, the model minutes (every harness pass of each stage's per-pass ledger, from its progress comment's ledger line or its usage record), the wall clock (from the Objective's start to the merge, the scorer's rule: its first `pendulum:objective` or `pendulum:running` label, or for one filed as a draft the start that led to its first Running), the review rounds (review stages) and the fix passes; and its runs of unknown cost with their reasons. A kind's median counts every measured merged Objective, so one billed at another kind counts as $0 in it. A merged Objective with a run of unknown cost is left out of every dollar measure, and one whose measure was not recorded out of that measure (model minutes and fix passes: a stage with no ledger, or a stage comment Pendulum cannot attribute to itself; wall clock: no start event); each is counted as `leftOut`. The medians and quartiles interpolate between the closest ranks, the same computation as the bench's baseline line.
- **No claims.** The figures stand alone: no difference between the arms, no test of significance, no total across kinds or across arms. Every measure carries its n, and the Markdown shows each arm's rows under the table. The Markdown shows the comparison and the source only; the JSON's `totals`, `breakdowns`, `objectives` and `hotSpots` cover both arms together.

## Rules

- Dollars are vendor-reported (Claude Code's `total_cost_usd`, Copilot's AI credits, the AI Gateway's cost, the sandbox vendor's usage at its list rates), or API-reported tokens at the published rate (the Codex price table), or unknown. Nothing is estimated, bounded or counterfactual. The figures are the scorer's own: both use one cost join (`plugin/scripts/lib/cost-join.mjs`), each stage counted once across its usage record and its spend line.
- Totals stay split by kind and are never added together: `api` (billed per use on a key), `subscription` (API-equivalent at list prices, on the subscription), `credits` (Copilot AI credits, billed to the seat), `unknown` (billing not recorded) and `sandbox` (the cloud sandbox vendor's cost). The report carries no total across kinds.
- Spend that was not reported is a count of runs of unknown cost, each with its reasons, never $0.
- Hot spots are ranked by exact counts and ratios of them; nothing is flagged against a threshold.
- No reason, Block text, task card, transcript or credential string is in the report, and no account unless `--by account` asks for it.

## Schema

The JSON's `schema` is `pendulum-report/1`. A change that renames, removes or retypes a field is a new version; a new field is not, so `comparison` and `scope.compare` are fields of `pendulum-report/1`. Dollars are US dollars, rounded to a millionth. A **cost** is `{usd: {api, subscription, credits, unknown, sandbox}, unknownRuns, unknownWhy}`: the known dollars of each kind (0 for none), the runs of unknown cost and their reason codes. **Tokens** are `{input, output, cached, written}`, summed where a record reports them (input includes the cache reads and writes), null where none does.

| Field | What it holds |
| --- | --- |
| `schema` | `pendulum-report/1` |
| `repository` | `OWNER/NAME` |
| `generatedAt` | When the report was made (ISO) |
| `pendulum` | The Pendulum release that made it |
| `scope` | `since`, `until` (ISO or null), `defaultPeriod`, `issues`, `label`, `parent`, `compare` (the two arms' label names, or null), `by` (the extra breakdowns asked for) |
| `words` | The words for each cost kind, to label the figures with exactly |
| `totals` | `objectives`, `stages`, `passes` (from per-pass ledgers), `cost`, `tokens` |
| `unknown` | `runs`; `reasons`: `{code, stages, runs, text}` per reason code, `stages` the stages (and decision records) naming it and `runs` its runs where no stage gives it with another reason, else null; `items`: `{issue, stage, runs, why}` per stage with unknown cost |
| `breakdowns` | `stage` (`work`, `rebase`, `review`, `decisions`: the decision calls outside a stage), `pass` (by pass label: the ledger label without its count, `work-2` as `work`; from the ledgers, with `modelMinutes`), `model`, `harness`, `version` (the Pendulum release that ran the stage), and `account` with `--by account`. Each row: `key` (null where no record names it), `stages` (`passes` for `pass`), `cost`, `tokens`. Every breakdown but `pass` covers the totals |
| `objectives` | One row per Objective: `issue`, `title`, `url`, `outcome` (`blocked` or `question` by its state label; else `open` while the issue is open; else `merged` when the newest PR on `pendulum/<n>` from the repository itself, not a fork, merged, or `closed-unmerged`; null when its issue, or for a closed one its PRs, could not be read), `stages` (`work`, `rebase`, `review` counts), `passes` (`total`, `answer`, `fix`; null without a ledger for every stage), `cost`, `tokens`, `modelMinutes`, `usdPerModelMinute` (per billing kind: that kind's `usd` over the `modelMinutes` of the `passes` whose dollars were all reported, the same minutes for every kind; never summed across kinds), `unpricedPasses` |
| `hotSpots` | Each `{rankBy, items}`, ranked by `rankBy`, largest first: `reviewLoops` (review stages per Objective), `answerAndFixPasses` (answer and fix passes per Objective; `unrecorded` lists the Objectives with no ledger), `cacheWriteShare` (per pass label: `passLabel`, `passes`, `written`, `input`, `share`), `costPerModelMinute` (per Objective and billing kind), `blockedOrUnmergedSpend` (the Objectives that ended Blocked or closed unmerged, with their `stages` and `cost`) |
| `comparison` | Null without `--compare` or `--compare-label`. Else `inBoth` (issues both labels count for, in neither arm) and `arms`, two, in the order given: `label`, `experiment` (its name, or null for another label), `n`, `outcomes` (a count per outcome, `unread` for null), `merged`, `usdPerMerged` (per cost kind), `modelMinutes`, `wallMinutes`, `reviewRounds`, `fixPasses`, each `{median, p25, p75, n, leftOut}` over the merged Objectives (null where none has the measure); `unknown` (`runs`, `objectives`, `reasons`: `{code, objectives, text}`); `untrusted`, `unverifiable` and `unchecked` (issues with the label not counted: its last applier cannot push, its applier's permission could not be read, or the call budget stopped before the check); `objectives` (per Objective: `issue`, `outcome`, `usd` per kind, `unknownRuns`, `modelMinutes`, `wallMinutes`, `reviewRounds`, `fixPasses`) |
| `source` | `complete`, `stoppedAt`, `maxCalls`, `calls` (`planned`, `plannedAtLeast`, `made`, `byKind`), `trusted` (`logins`, `app`, `appFrom`: `flag`, `variable` or `env`), `read` (comments, Pendulum's own, not attributed and ignored; issues, PRs, artifacts listed, downloaded, cached, expired, failed, unreadable and from forks; local records) and `missing`: `{code, count, issues, text}` for each thing that was not read or not recorded (`ledger-stopped` adds `stages`) |

`missing` codes: `stopped` (the call budget ended the reads), `stopped-before-records` (Objectives whose usage records the budget did not reach, for stages with no spend line), `ledger-stopped` (stages with a spend line whose per-pass ledger the budget did not reach; its entry also lists them, `stages`: `{issue, stage, key}`), `self-unknown`, `app-not-given`, `unattributed`, `no-record` (a stage with no spend line and no usage record read), `artifact-foreign` (usage artifacts from runs of forks, or naming no repository id, never read), `no-ledger` (stages without a per-pass ledger in their comment or usage record: stages from before it, or a local stage whose ledger did not fit its comment and that has no local record on this machine), `no-version`, `issue-unread`, `label-untrusted` (issues whose vetted label was last applied by someone who cannot push, a bot or an App), `label-unverifiable` (issues whose label's last applier's permission the token may not read), `label-unchecked` (issues whose label's applier the call budget stopped the report before reading), `in-both-arms`, `artifact-expired`, `artifact-failed`, `artifacts-unreadable` (lists the token may not read, or artifacts that name no workflow run).

## The per-pass ledger

Each stage's usage record (`result.json`: the GitHub Actions artifact `pendulum-usage-<n>[-review]`, or local mode's `<clone>/.pendulum/<n>/usage-*/`) carries `ledger`, one entry per harness pass and decision record: `label`, `decision` and `calls` for a decision record, `model`, `effort`, `started`, `ended`, `usd`, `usdUnknown`, `usdUnknownWhy`, `billing`, `usdByBilling` (its dollars by kind, a relayed key's share as `api`), `workerKeyUsd`, `tokens`, `resumed` and `firstCache` (its first request's cache split). Its `ran` names the worker's and the reviewer's effort and the Pendulum release (`pendulum`). The artifact keeps it 90 days, and the report's cache keeps what it read.

Every stage, on every route, also writes its ledger into its progress comment, on the line after its spend line, when the stage ends: `<!-- pendulum:ledger {...} -->`, numbers and labels only (no reason, Block text, prompt, path or credential). Its keys are short: `v` (the Pendulum release), `m` (the stage's model), `b` (the first pass's billing) and `p`, one entry per pass with `l` (label), `d` (a decision record's calls), `m` and `b` where the pass's differ from the stage's, `e` (effort), `t` (start and end, Unix seconds, so to the second), `u` (known dollars, to a millionth, as the spend line), `q` and `w` (runs of unknown cost and their codes), `y` (dollars by billing, where they are not all at the pass's own kind), `k` (a relayed key's share), `n` (input, output, cached and written tokens), `r` (1 when it resumed a session) and `c` (its first request's cache read and write). A model is written only when the stage's harness line already names it (its own, or the Objective's worker, sub-agent or reviewer model), so an id the harness resolved itself (a Bedrock inference profile ARN names an AWS account) never reaches the comment: a pass on another model reads as `m: null`. A stage whose harness line names no model at all (Copilot at its default) writes its own model from its usage record, a name from GitHub's model catalog. A ledger is not written when its line would pass 6,000 characters, or when it would take the comment past 60,000 (GitHub refuses one over 65,536): the comment says so in a line of its own, the marker carries the pass count alone (`{"cut": N}`), and the usage record stays that stage's ledger. The report reads the line for a stage's passes, tokens (its passes' summed), model and release, and the finish card for its model; both only on Pendulum's own comments (Trust, above), and neither for dollars: a stage's dollars are always its spend line's. Where a stage's usage record or local record is at hand, the report takes its ledger from it instead, its times to the millisecond; from the comment, pass minutes are to the second.
