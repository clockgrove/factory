# The cost report

`pendulum report` reads what Pendulum's own records say about a period or a set of Objectives and prints every figure already computed: as JSON with `--json` (the schema below), else as plain Markdown for a terminal or CI. Pendulum is only the data layer. Your coding agent presents the JSON however you ask (a table, a chart, an HTML page, a document) through the [`/pendulum:pendulum-report`](../plugin/skills/pendulum-report/SKILL.md) skill, and it never adds, averages or derives a dollar figure itself.

```sh
pendulum report [--since DATE] [--until DATE] [--issue N[,N...] | --label NAME | --parent N] [--json] [--max-calls N] [--by account|pass] [--app ID] [--self LOGIN]... [--repo OWNER/NAME]
```

- **Scope.** `--since` and `--until` (a date, or a time with its zone; `--until` is exclusive) give a period: every Objective with a stage that started in it. `--issue`, `--label` and `--parent` (the parent issue's sub-issues) give a set of Objectives, read whole unless a period is given too. A period with no `--since` (and no set) starts 30 days before `--until`, or before now, at that day's UTC midnight (`scope.defaultPeriod`). A decision-spend line, which records one UTC day's decision calls, counts when that day's start (its midnight) falls in the period.
- **Reads.** The issue comments hold every marker the report needs: the progress, harness, spend, vendor, decision-spend and finish markers. For `--issue`, each named issue's own comments are read; otherwise one paged repository-wide read (`issues/comments?since=`). The Objectives' issues and the PRs on their `pendulum/<n>` branches give each one's outcome (for `--issue`, each branch's own PRs). A merged Objective is read from its finish card's summary (below) when the card is Pendulum's own, its run (its clock to its merge) lies in the period, and every stage comment of the Objective in the period is one the card counted; its stage comments and usage artifacts are then not read. `--by account` and `--by pass` read every stage instead: an account, the per-pass ledger, tokens and the Pendulum release of each stage are in its own records only. Usage artifacts are listed and read for the stages whose spend line does not say everything: a stage with no spend line, for its dollars, and a stage whose spend line has no per-pass detail (a spend line never carries the ledger) and whose ledger no local record in this clone holds, for its per-pass ledger, tokens, Pendulum release and (when its harness line names none, as Copilot's at its default model) model alone. A stage with a spend line keeps that line's dollars, so none is counted twice; a spend line carries no tokens. The Objectives with a stage that has no spend line are read first, so a call budget that runs out costs per-pass detail before a dollar figure. A record that names a stage comment the report does not attribute to Pendulum is that stage's: it adds no stage and no dollars. Artifacts uploaded before the period began are not read. An artifact a fork's run uploaded (its workflow run's head repository is not the repository), or one that names no repository id, is never read, whatever its name: it is counted as `artifact-foreign`. Each artifact read is downloaded with `gh run download`, which reads its run's artifact list, and kept by its artifact id under your cache directory (`$XDG_CACHE_HOME`, else `~/.cache`; `~/Library/Caches` on macOS), in `pendulum/artifacts/<API host>/<owner>/<name>/`, with only the fields the report reads, never in the repository, so a later report downloads it no more. Local mode's own records under `<clone>/.pendulum/<n>/` are read for the per-pass ledger when the command runs in the clone. No timeline, job or list of workflow runs is read, and nothing is written.
- **Budget.** The command prints its planned GitHub API calls to stderr before it reads: a paged read's first page, then, from that page's `Link` header, the pages left (said as "at least" where GitHub names no last page); for `--issue`, each issue's comment pages from its comment count; after an Objective's artifact lists, the downloads its artifacts not yet cached take, two each. A merged Objective read from its summary plans no artifact read. It stops at `--max-calls` (300 by default). A stopped report still prints what was read, with `source.complete` false, and exits 3: an Objective whose PRs were not read has no outcome (null) unless a state label or an open issue decides it, and a stage whose usage record was not reached is of unknown cost for `stopped`.
- **Token.** Local mode's token for the repository when it is saved, else your `gh` login: the report shows only what that login can read.
- **Trust.** A marker counts only from Pendulum's own login (the token's), a login `--self` names (each one, exactly, and only on a comment by someone who can push), or Pendulum's App. The App's numeric id comes from `--app`, else the repository variable `PENDULUM_APP_ID` (one call; `pendulum setup` writes it beside the secret of that name), else `PENDULUM_LOCAL_APP_ID`. A stage comment by anyone else who can push, or through another GitHub App, is a stage of unknown cost (`unattributed`), never its figures; its vendor comment adds nothing to it, one with no progress comment is a run of unknown cost but no stage, and its decision-spend lines are decision calls of unknown cost. Anyone else's, `github-actions[bot]` included, counts nothing. A finish card's summary counts only on Pendulum's own comment, as every marker does; anyone else's card is no summary, and the Objective's stages are read. `source.trusted` lists the logins and the App the report trusted. For an install from before the variable, save it once: `gh variable set PENDULUM_APP_ID --repo OWNER/NAME --body <the App's numeric id>` (doctor names the same line on GitHub Actions when it is missing or names another App).

## Rules

- Dollars are vendor-reported (Claude Code's `total_cost_usd`, Copilot's AI credits, the AI Gateway's cost, the sandbox vendor's usage at its list rates), or API-reported tokens at the published rate (the Codex price table), or unknown. Nothing is estimated, bounded or counterfactual. The figures are the scorer's own: both use one cost join (`plugin/scripts/lib/cost-join.mjs`), each stage counted once across its usage record and its spend line.
- Totals stay split by kind and are never added together: `api` (billed per use on a key), `subscription` (API-equivalent at list prices, on the subscription), `credits` (Copilot AI credits, billed to the seat), `unknown` (billing not recorded) and `sandbox` (the cloud sandbox vendor's cost). The report carries no total across kinds.
- Spend that was not reported is a count of runs of unknown cost, each with its reasons, never $0.
- Hot spots are ranked by exact counts and ratios of them; nothing is flagged against a threshold.
- No reason, Block text, task card, transcript or credential string is in the report, and no account unless `--by account` asks for it.

## Schema

The JSON's `schema` is `pendulum-report/1`. A change that renames, removes or retypes a field is a new version; a new field is not. Dollars are US dollars, rounded to a millionth. A **cost** is `{usd: {api, subscription, credits, unknown, sandbox}, unknownRuns, unknownWhy}`: the known dollars of each kind (0 for none), the runs of unknown cost and their reason codes. **Tokens** are `{input, output, cached, written}`, summed where a record reports them (input includes the cache reads and writes), null where none does.

| Field | What it holds |
| --- | --- |
| `schema` | `pendulum-report/1` |
| `repository` | `OWNER/NAME` |
| `generatedAt` | When the report was made (ISO) |
| `pendulum` | The Pendulum release that made it |
| `scope` | `since`, `until` (ISO or null), `defaultPeriod`, `issues`, `label`, `parent`, `by` (the `--by` values asked for: `account` adds the account breakdown; either reads every stage, no Objective from its summary) |
| `words` | The words for each cost kind, to label the figures with exactly |
| `totals` | `objectives`, `stages`, `passes` (from per-pass ledgers), `cost`, `tokens` |
| `unknown` | `runs`; `reasons`: `{code, stages, runs, text}` per reason code, `stages` the stages (and decision records) naming it and `runs` its runs where no stage gives it with another reason, else null; `items`: `{issue, stage, runs, why}` per stage with unknown cost |
| `breakdowns` | `stage` (`work`, `rebase`, `review`, `decisions`: the decision calls outside a stage), `pass` (by pass label: the ledger label without its count, `work-2` as `work`; from the ledgers, with `modelMinutes`), `model`, `harness`, `version` (the Pendulum release that ran the stage), and `account` with `--by account`. Each row: `key` (null where no record names it), `stages` (`passes` for `pass`), `cost`, `tokens`. Every breakdown but `pass` covers the totals |
| `objectives` | One row per Objective: `issue`, `title`, `url`, `outcome` (`blocked` or `question` by its state label; else `open` while the issue is open; else `merged` when the newest PR on `pendulum/<n>` from the repository itself, not a fork, merged, or `closed-unmerged`; null when its issue, or for a closed one its PRs, could not be read), `stages` (`work`, `rebase`, `review` counts), `passes` (`total`, `answer`, `fix`; null without a ledger for every stage), `cost`, `tokens`, `modelMinutes`, `usdPerModelMinute` (per billing kind: that kind's `usd` over the `modelMinutes` of the `passes` whose dollars were all reported, the same minutes for every kind; never summed across kinds), `unpricedPasses` |
| `hotSpots` | Each `{rankBy, items}`, ranked by `rankBy`, largest first: `reviewLoops` (review stages per Objective), `answerAndFixPasses` (answer and fix passes per Objective; `unrecorded` lists the Objectives with no ledger), `cacheWriteShare` (per pass label: `passLabel`, `passes`, `written`, `input`, `share`), `costPerModelMinute` (per Objective and billing kind), `blockedOrUnmergedSpend` (the Objectives that ended Blocked or closed unmerged, with their `stages` and `cost`) |
| `source` | `complete`, `stoppedAt`, `maxCalls`, `calls` (`planned`, `plannedAtLeast`, `made`, `byKind`), `trusted` (`logins`, `app`, `appFrom`: `flag`, `variable` or `env`), `read` (comments, Pendulum's own, not attributed and ignored; issues, PRs, artifacts listed, downloaded, cached, expired, failed, unreadable and from forks; local records) and `missing`: `{code, count, issues, text}` for each thing that was not read or not recorded (`ledger-stopped` adds `stages`) |

`missing` codes: `stopped` (the call budget ended the reads), `stopped-before-records` (Objectives whose usage records the budget did not reach, for stages with no spend line), `ledger-stopped` (stages with a spend line whose per-pass ledger the budget did not reach; its entry also lists them, `stages`: `{issue, stage, key}`), `self-unknown`, `app-not-given`, `unattributed`, `no-record` (a stage with no spend line and no usage record read), `artifact-foreign` (usage artifacts from runs of forks, or naming no repository id, never read), `no-ledger` (stages without a per-pass ledger: records from before it, or a local stage with no local record on this machine), `no-version`, `issue-unread`, `artifact-expired`, `artifact-failed`, `artifacts-unreadable` (lists the token may not read, or artifacts that name no workflow run), `summary` (merged Objectives read from their finish card's summary: their figures are the card's, with no tokens, per-pass ledger or Pendulum release by stage; their `passes`, `modelMinutes` and `tokens` are null, their stages are under a null `version`, and `--by pass` reads their stages instead).

## The finish card's summary

Each finish card ([USAGE.md](USAGE.md#the-finish-card)) carries one hidden line under its `<!-- pendulum:<n>:finish -->` marker: `<!-- pendulum:<n>:summary {...} -->`, its JSON on one line with `<` and `>` escaped. It holds the figures the card shows, from the same records the card is drawn from, never worked out another way. `v` is its version, `1`: a change that renames, removes or retypes a field is a new version, and a reader reads the Objective's stages for a version it does not take, or for a summary any figure of which does not read. Dollars are US dollars to a millionth, `cents` the whole cents the card shows (its rows add up to the total's), times are ISO and `ms` milliseconds.

| Field | What it holds |
| --- | --- |
| `v`, `pendulum`, `issue` | The summary's version, the Pendulum release that posted the card, and the issue |
| `started`, `merged`, `wallMs` | The card's clock (the label that started the run), the merge, and the wall clock between them |
| `prs`, `commits`, `additions`, `deletions`, `files` | The merged PRs and their change, every part of a split Objective added up |
| `checks`, `reviews` | `{passed, failed, required}` of the checks that gated the merge, and `{count, findings}` of Pendulum's reviews; each null for none |
| `stageCounts` | `{work, rebase, review}` as the report counts stages: a build and a split part are `work` |
| `cost` | `{usd, cents, unknown, why, byBilling}`: the known dollars, the runs of unknown cost with their reason codes, and the dollars by billing kind; the cloud sandbox's dollars are in it, and apart below |
| `sandbox` | The cloud sandbox's own cost `{usd, cents, unknown, why}`, or null: `why` is `sandbox` for a stage's own vendor comment and `unattributed` for one Pendulum cannot attribute |
| `stages` | In time order: `kind` (`build`, `part`, `work`, `rebase`, `review`), `part`, `model`, `harness`, `ms` (null for a stage with no progress comment), `usd` (null: none known), `cents`, `unknown`, `why`, `byBilling`, `sandbox` (its own vendor comment's `{usd, unknown}`, or null) and `churn` (its churn rows' codes) |
| `asked` | Where the dollars went, the work the issue asked for: `{part, what, usd, cents, unknown, byBilling}`, `what` one of `work`, `review`, `answer`, `fix`, or `sandbox` for the cloud sandbox's row |
| `churn` | The churn Pendulum caused: `{row, stages, usd, cents, unknown, byBilling}`, `row` one of `rebase-conflict`, `rebase-clean`, `catch-up`, `judge`, `block` |

## The per-pass ledger

Each stage's usage record (`result.json`: the GitHub Actions artifact `pendulum-usage-<n>[-review]`, or local mode's `<clone>/.pendulum/<n>/usage-*/`) carries `ledger`, one entry per harness pass and decision record: `label`, `decision` and `calls` for a decision record, `model`, `effort`, `started`, `ended`, `usd`, `usdUnknown`, `usdUnknownWhy`, `billing`, `usdByBilling` (its dollars by kind, a relayed key's share as `api`), `workerKeyUsd`, `tokens`, `resumed` and `firstCache` (its first request's cache split). Its `ran` names the worker's and the reviewer's effort and the Pendulum release (`pendulum`). The ledger is not written to GitHub: the artifact keeps it 90 days, and the report's cache keeps what it read.
