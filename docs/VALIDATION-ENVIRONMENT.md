# Validation environment

Factory validation (a Work Item's commands, environment readiness, final validation) runs in a sandbox that differs from a target repository's hosted CI. This is the one list of those differences. The planner receives a compact form of it (`src/planning/facts.ts`), and `factory setup --config-only` reports the installation's facts under `readiness.validationEnvironment`.

Rule: a command that needs something below and is not provided is a CI-only command. List it in `finalValidation.ciOnlyCommands` ([user guide](USER-GUIDE.md)); the planner then leaves it out and asks through `decisionRequired` when a criterion needs it. Each worker is told the CI-only commands and never to run them in its offline checkout.

Validation runs the host's node from the service's PATH. When the target pins Node (`.nvmrc`, `.node-version`, `.tool-versions` or `engines.node`), setup and the Objective check flag a host node that doesn't satisfy the pin. When the target pins its tools with mise and mise is on the setup shell's PATH, `factory setup --background` puts the pinned versions first on the service's PATH ([Toolchain from mise](reference/setup.md#toolchain-from-mise)).

| Private temporary space and sandbox restrictions                                                                                                                     | A fresh empty `TMPDIR`, `TMP`, `TEMP`, private `HOME` and `/tmp`, read-only host, no host socket files (under `sandbox.network` `host`, TCP to the host's loopback services stays open), bounded resources                                                                                                                                            | Write only under the checkout or the temporary directory; no host paths, sockets or home-directory state                                                                                                                                                                                                                                                                                |

Tools provisioned on the host (a pinned browser for a browser-automation library, say) are reachable read-only: list their directory in `sandbox.readOnlyPaths` and point the tool at it with `sandbox.environment` (for example `PLAYWRIGHT_BROWSERS_PATH`). The values are fixed, operator-configured strings applied to every sandboxed command; `factory setup --config-only` lists the names under `readiness.validationEnvironment.environment` and warns when an absolute-path value is not covered by `readOnlyPaths`. Names Factory controls or that could leak credentials are refused. A Codex worker's shell gets the same read-only paths, checked the same way, and the same variables; Factory's own variables win.

Setup warns when a package script body invokes a known network tool (by command word, never by matching prose) and its `npm run NAME` or `pnpm run NAME` is not in `ciOnlyCommands`.
