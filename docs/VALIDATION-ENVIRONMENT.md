# Validation environment

Factory validation (a Work Item's commands, environment readiness, final validation) runs in a sandbox that differs from a target repository's hosted CI. This is the one list of those differences. The planner receives a compact form of it (`src/planning/facts.ts`), and `factory setup --config-only` reports the installation's facts under `validationEnvironment`.

Rule: a command that needs something below and is not provided is a CI-only command. List it in `finalValidation.ciOnlyCommands` ([user guide](USER-GUIDE.md)); the planner then leaves it out and asks through `decisionRequired` when a criterion needs it.

| Difference                                                                                                                                | Factory provides instead                                                                                                                                    | A target repo must                                                                                                                                    |
| ----------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| No network, except the verified dependency install when `sandbox.network` is `package-install`                                            | A warm `sandbox.packageStore` for offline installs                                                                                                          | List network commands (registry, license, advisory checks, `tofu init`, `terraform init`, `curl`) in `ciOnlyCommands`, exactly as Objectives run them |
| Package bootstrap (`npm ci --ignore-scripts`, `pnpm install --frozen-lockfile --ignore-scripts`) is the only install, and only runs first | Factory hoists the bootstrap to the front of every validation sequence                                                                                      | Not rely on install lifecycle scripts or a later install                                                                                              |
| Remote-tracking branches such as `origin/main` can be stale; Factory fetches by SHA                                                       | `FACTORY_BASE_SHA`, the Objective's accepted base commit, in controller validation (not a worker's own `Validate` runs)                                     | Compare with `${FACTORY_BASE_SHA:-origin/main}` in base-relative checks                                                                               |
| No hosted CI jobs, logs, secrets or services                                                                                              | After a failed CI check on a published head, repair evidence carries an excerpt of the failing check's log                                                  | Treat CI-only proof as CI's job; do not expect it in validation                                                                                       |
| Test environment is scrubbed                                                                                                              | A private, empty HOME for the whole command sequence, an empty TMPDIR per run, and an empty GitHub CLI config; no host credentials, tokens or user settings | Don't rely on host credentials, global caches or user config; create what a test needs inside its own temporary directory                             |
| Private temporary space and sandbox restrictions                                                                                          | A fresh empty `TMPDIR`, `TMP`, `TEMP`, private `HOME` and `/tmp`, read-only host, no host sockets, bounded resources                                        | Write only under the checkout or the temporary directory; no host paths, sockets or home-directory state                                              |

Tools provisioned on the host (a pinned browser for a browser-automation library, say) are reachable read-only: list their directory in `sandbox.readOnlyPaths` and point the tool at it with `sandbox.environment` (for example `PLAYWRIGHT_BROWSERS_PATH`). The values are fixed, operator-configured strings applied to every sandboxed command; `factory setup --config-only` lists the names under `validationEnvironment.environment` and warns when an absolute-path value is not covered by `readOnlyPaths`. Names Factory controls or that could leak credentials are refused. A Codex worker's shell gets the same read-only paths, checked the same way, and the same variables; Factory's own variables win.

Setup warns when a package script body invokes a known network tool (by command word, never by matching prose) and its `npm run NAME` or `pnpm run NAME` is not in `ciOnlyCommands`.
