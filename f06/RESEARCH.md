# Facts the lanes build on (verified Nov 2, 2026; cite the plan for intent, this file for mechanics)

## Headless harness launch and credentials
- Claude Code: `claude -p "<prompt>" --output-format json` (or `stream-json` with `--verbose`). Credential: `ANTHROPIC_API_KEY`, or workload identity federation in CI (job `id-token: write`, exchanged for a short-lived token; the official `anthropics/claude-code-action` does this), or the opt-in plan token `CLAUDE_CODE_OAUTH_TOKEN` for a developer's own repo. If both an API key and the OAuth token are set, the API key wins silently. `--max-budget-usd <n>` ends the run when the estimate trips (result `subtype` becomes `error_max_budget_usd`). JSON result carries `total_cost_usd`, `usage` (top level excludes sub-agents), `modelUsage` keyed by model (includes sub-agents; use this for whole-run accounting), `num_turns`, `is_error`. Sub-agents: `.claude/agents/<name>.md` with frontmatter `name`, `description`, `tools`, `model` (alias like `sonnet`/`opus`/`haiku`, a full model id, or `inherit`). Skills: `.claude/skills/<name>/SKILL.md`. Plugins: `claude plugin marketplace add <owner/repo>`; `claude plugin install <plugin>@<marketplace>`; marketplace manifest in the marketplace repo. Cloud sessions do not install repo-declared plugins but do load committed `.claude/` directories; the cloud proxy blocks GraphQL (`gh pr`/`gh issue` fail; use `gh api` REST).
- Codex CLI: `codex exec --json "<prompt>"` emits JSONL (`thread.started`, `turn.started`, `item.*`, `turn.completed` with `usage.input_tokens`, `usage.cached_input_tokens`, `usage.output_tokens`; reasoning tokens may be missing). Credential: `CODEX_API_KEY` set on the single step that runs it, never job-level (OpenAI's warning). No USD in output; price from a table. Sub-agents on by default; custom agents in `.codex/agents/<name>.toml` with `name`, `description`, `developer_instructions`, optional `model`, `model_reasoning_effort`; pin `model` in the file (a spawn-time model arg is dropped for role agents). Global `[agents]` has `default_subagent_model`, `default_subagent_reasoning_effort`, `max_concurrent_threads_per_session`. Skills: `.agents/skills/<name>/SKILL.md`. Plugins: `codex plugin marketplace add owner/repo`, `codex plugin add <plugin>`; marketplace file `.agents/plugins/marketplace.json`; plugin manifest `.codex-plugin/plugin.json`. In non-interactive runs an action needing new approval fails.
- Copilot CLI: `copilot -p "<prompt>" --allow-all --output-format json --usage-output-file <file>` (1.0.91: `--allow-all` covers tools, paths and URLs and is required for non-interactive runs; `--resume <id>` continues a session; `--max-ai-credits` caps a session; there is no `--no-ask-user`). Credential in Actions: the job's `GITHUB_TOKEN` with `permissions: copilot-requests: write` (org-billed; the org policy "Allow use of Copilot CLI billed to the organization" must be on), else `COPILOT_GITHUB_TOKEN` as a fine-grained PAT with Copilot Requests (bills the user's seat). Per-run usage: `--usage-output-file` writes final token counts and premium requests as JSON; dollars are not reported, billing is GitHub AI Credits (token-based since June 2026). Custom agents: `.github/agents/<name>.agent.md` with frontmatter `name`, `description`, `tools`, `model` (single string on CLI), `model-policy: required`; invoke `copilot --agent <name>`. Skills read from `.github/skills/`, `.claude/skills/`, `.agents/skills/`.
- Portable skill location: ship one tree at `.agents/skills/` and mirror to `.claude/skills/`.

## GitHub mechanics
- A PR opened, pushed or enqueued with the job's `GITHUB_TOKEN` gets no `merge_group` workflow run (and `pull_request` runs only in an approval-required state), so required checks never report and the merge queue evicts it at its timeout. Use a GitHub App installation token (`actions/create-github-app-token`) for push, PR creation, review requests, Project card moves and `gh pr merge --auto`. Keep the job token read-only on code.
- The merge queue needs required checks reported on the queue's commit, so CI must be a separate workflow triggered on `pull_request` and `merge_group`. `merge_group` supports only `checks_requested`. A skipped required check counts as passed; aggregator jobs use `if: always()` with `needs`.
- `GITHUB_TOKEN` cannot push to `.github/workflows/` and cannot write Projects (v2); the App needs contents, pull requests, issues and projects permissions. Projects v2 is GraphQL (`gh api graphql`), fine on Actions runners.
- Job timeout: 6 h on hosted runners, 5 days self-hosted. `permissions:` can be scoped per key; unlisted keys become none; add `id-token: write` only for Claude federation and `copilot-requests: write` only for Copilot.
- Concurrency groups hold one running + one pending job and cannot cap at N; a pending job is replaced (cancelled) by a newer one. Use a per-issue group (`factory-<issue>`) for dedupe and a `strategy.matrix` with `max-parallel: N` over ready issues for the global cap.
- Mobile notifications from a bot actor's @mention or review request are undocumented; the plan tests them on the owner's phone at step 3.
