# Factory 0.6 Action: notes from the Action and worker lane

> Layout since Nov 3: the scripts, their tests and `workflow-template.yml` live in `../plugin/` (the plugin is self-contained; an installed plugin must reach its own scripts). `action/` holds `action.yml`, which runs `../plugin/scripts/*.mjs` through `FACTORY_PLUGIN_ROOT`. Paths below that say `scripts/` mean `plugin/scripts/`.

## What is here

```
action.yml                 composite action, mode: dispatch | work | review
workflow-template.yml      the file an adopter commits (replaces plugin/templates/factory.yml; see below)
scripts/dispatch.mjs       ready list -> matrix JSON; marks picked issues Running; Done and relabel reconcile
scripts/worker.mjs         one Objective: doctor, branch, plugin into checkout, setup, harness, PR, validation x2, exit
scripts/review.mjs         one reviewer pass -> PR review; one worker pass; validation; auto-merge
scripts/doctor.mjs         the plan's Doctor checks, PASS/WARN/FAIL + fix; jobChecks() is the worker's first step
scripts/setup.mjs          labels, Project (GraphQL), ruleset (REST), workflow file; --yes applies; never creates an App
scripts/lib/               app-token (JWT + installation token, no deps), token-keeper (re-mints hourly), harness
                           (command lines, credential scoping, federation), checkout (plugin install, git-exclude,
                           branch, install command), session (git identity, pre-commit guard, validation loop,
                           exits), github (gh api REST/GraphQL), logic (pure, tested), usage (parsers), proc, inputs
test/                      30 node --test tests; fixtures from the shapes in RESEARCH.md
```

Tests: `node --test 'test/*.test.mjs'` passes 30/30 on Node 22.23. Every script passes `node --check`; `action.yml` and the rendered workflow parse as YAML.

## Interfaces changed from lane 1

1. **`templates/factory.yml` is replaced by `workflow-template.yml` here.** Lane 1 wrote a reusable-workflow call (`uses: clockgrove/factory/.github/workflows/factory.yml@v1`) with `secrets: inherit`. I made the Action a composite action called three times, because: (a) a reusable workflow cannot be `strategy.matrix`-ed over a list the caller computes in the same run without a second reusable workflow, (b) `secrets: inherit` passes every repository secret into Factory, which the footprint section forbids in spirit, and (c) the `pull_request` review trigger must be in the adopter's own file for the App-applied label to fire it. The file is ~90 lines, not ~30: the three jobs with their `permissions`, `concurrency`, `timeout-minutes`, matrix and artifact upload are what the plan's Scale section asks for and cannot be hidden in the action. The inputs live in one `env:` block at the top (`FACTORY_*`), which is what an adopter edits; `/factory setup` fills it. `factory-setup` should read `workflow-template.yml` from the action checkout rather than `templates/factory.yml`; the placeholder names are lane 1's (`{{harness}}` ... `{{validation}}`) plus `{{budget_command}}`, `{{protected_paths}}`, `{{ci_checks}}`, `{{version}}`, `{{runs_on}}`.
2. **Script flags.** Adopted lane 1's `--repo`, `--json`, `--issue`; `--apply <step>` takes `labels|project|protection|workflow|all` (comma-separated), and `--yes` is required to change anything (a bare call is a dry run). Added `--pr` (review), `--checkout`, `--usage-dir`, `--out`, `--ci-checks`, `--probe` and `--run-setup` (doctor's slow checks), `--dry-run` (dispatch). Any workflow input is also a flag (`--max-usd 20`); precedence is flag, then `with:` (`FACTORY_INPUT_*`), then the workflow `env:` block (`FACTORY_*`), then the default in `lib/inputs.mjs`.
3. **Usage artifact.** Name `factory-usage-<issue>` as lane 1 assumed; contents are `events.jsonl` (the harness's raw stdout, for every harness, with `factory.run` markers between runs) **and** `result.json` (normalized, for every harness), so `/factory score` reads `result.json` first and `events.jsonl` only for detail. The review job uploads `factory-usage-<issue>-review` (one name, `overwrite: true`, so the bench lists it exactly); the dispatcher sums both into `daily_usd`. `result.json` carries `exit`, `reason`, `passes`, `runs` and `credential` beside the plan's fields.
4. **Markers.** Lane 1's `<!-- factory:<issue>:plan -->` is honoured (the worker reads it for the QUESTION test). Added `factory:<issue>:blocked:<stage>`, `factory:<issue>:validated:<sha>` (a PR comment the worker posts when its validation is green) and `factory:<issue>:review` (in the review body, so the pass is never repeated).
5. **Labels.** Lane 1 used `factory:running`, `factory:blocked`, `factory:question`; I added `factory:in-review` (the plan's In review column) and `factory:review`, the PR label the App applies to make `pull_request(labeled)` fire the review job. `setup --apply labels` creates all of them plus P0..P2.
6. **Review posting.** The reviewer harness does not post; it returns `{"comments": [...]}` and `review.mjs` posts one COMMENT review through REST. Lane 1's `factory-review` skill posts from the session, which stays right for the plugin path.
7. **`/factory queue`** can call `dispatch.mjs` as lane 1 wrote; note it now also moves cards (Running, Done, Queued) and needs the App token (`FACTORY_APP_TOKEN` or app id + key), not the user's `gh` login, because Projects writes need the App.

## Assumptions

- **Local fallback.** Outside Actions, `credential: api` with no key present uses the CLI's own login (a WARN in doctor); inside Actions it is an error. Explicit `credential: login` means the same thing on purpose.
- **Harness flags.** Claude: `claude -p --output-format stream-json --verbose --dangerously-skip-permissions [--model] [--max-budget-usd] [--resume <session_id>]`, prompt on stdin. Codex: `codex exec --json --dangerously-bypass-approvals-and-sandbox --skip-git-repo-check [-m model] -` and `codex exec resume <thread_id> ... -` for the validation retry; prompt on stdin. Copilot (checked against `copilot --help` 1.0.91 on Nov 2): `copilot -p "<prompt>" --allow-all --output-format json [--model] [--agent reviewer] [--resume <id>] --usage-output-file <file>`; there is no `--no-ask-user`. The usage file's JSON keys are read tolerantly until a real run fixes them. Claude runs the reviewer as the pinned agent with `--agent reviewer`. These are the first thing a real runner will correct.
- **Federation.** RESEARCH.md says the OIDC token is exchanged for a short-lived Anthropic credential but not where. `anthropic_oidc_exchange_url` is an input; `federate()` POSTs `{oidc_token}` and accepts `api_key|token|access_token` in the reply. Without the URL, doctor FAILs and asks for a key. When the official exchange endpoint is known, hard-code it and drop the input.
- **Blocked-by relations.** `GET /repos/{o}/{r}/issues/{n}/dependencies/blocked_by` is tried first (GitHub's issue dependencies REST, 2025); on 404/410/403 the dispatcher parses `Blocked by #N` / `blocked-by: #N, #M` lines in the body. The log line `blocking from ...` says which was used.
- **Project card vs. label.** Card Status wins when it is not Queued; a Queued card with a `factory:blocked` label counts as Blocked (the label is the fallback written by the same jobs). Doctor FAILs without a board, per the plan's "the board is required"; the jobs themselves degrade to labels if a card move fails, so a missing board costs nothing mid-run.
- **Running at dispatch.** The dispatcher marks picked issues Running before the matrix starts, otherwise two cron ticks five minutes apart start the same issue twice (the per-issue concurrency group would queue the second, then run it after the first). The worker's doctor step re-marks Blocked on failure.
- **Recovery.** "Re-apply the label" is read from the issue timeline: the last `labeled factory:objective` event later than the last `labeled factory:blocked|question` event resets the state. `workflow_dispatch` with an issue number is the same intent and also resets.
- **Done.** No job runs on merge, so each dispatch tick finds `factory:objective` issues closed in the last 48 hours that still carry a state label or a non-Done card and moves them to Done. The review job appends `Closes #N` to the PR body when the worker left it out.
- **The review trigger.** `pull_request: [labeled, ready_for_review]` guarded by `startsWith(head_ref, 'factory/')`, same-repo head, and (for labeled) `label.name == 'factory:review'`. The worker applies `factory:review` with the App token after its validation is green, which is what makes the event fire (the job token's writes do not). A human marking a Question draft ready fires the same job. The review job removes the label when it is done; a rerun via re-labeling is one more pass, and the `factory:<issue>:review` marker makes the reviewer itself run once.
- **Validation loop.** Factory's own pass runs the `validation` commands with the model secrets scrubbed from the env. On red it sends the command, exit and 6 KB of tail to the same session (Claude `--resume`, Codex `exec resume`), or a fresh prompt (task card + failure) on Copilot, then runs the commands once more. Two passes, then Blocked ("validation red after Factory's second pass"). A green pass on an open PR outweighs a non-zero harness exit (max turns, a late tool error); with no validation commands the harness's own result stands.
- **Deaths.** A process that ends by signal, or non-zero with no turn recorded and no result subtype, is a death; one retry resumes the session (or re-sends the card on Copilot); the second death is Blocked.
- **Wall clock.** The worker's own deadline is `timeout_minutes - 8` so it can write the usage record and move the card before the runner kills the job; the fix pass gets a further 2-minute reserve. The workflow sets `timeout-minutes` from the same value.
- **Token life.** An installation token lasts an hour; a job may run six. `TokenKeeper` re-mints every 40 minutes and rewrites a token file (read by the git credential helper on every push) and a private `hosts.yml` (read by `gh` via `GH_CONFIG_DIR`), so the harness child never holds a stale token in its env. The scripts' own `gh api` calls use the getter. `GH_TOKEN` is deliberately absent from the harness env.
- **Git identity.** Commits are authored `<app-slug>[bot] <id+slug[bot]@users.noreply.github.com>`, looked up from `/users/<slug>[bot]`; falls back to `factory[bot]`.
- **Protected paths.** `.github/`, CODEOWNERS, `.agents/skills/`, `.claude/`, `.codex/` plus `protected_paths`. A pre-commit hook written per run refuses them; after the run the diff against the base is checked again and a hit is Blocked. The written skills and agents are added to `.git/info/exclude`; a repository skill of the same name is left in place (the override rule).
- **Offline install.** `install: auto` picks from the lockfile (pnpm/npm/yarn/cargo/poetry/uv/go); pnpm tries `--offline` first and falls back to a frozen online install because a hosted runner has no store. `install: none` skips; any other string is run as given.
- **Copilot billing token.** `COPILOT_GITHUB_TOKEN` is set to the job token for the Copilot child only, so the App token (also present through `hosts.yml`) is never billed for Copilot. Doctor cannot verify `copilot-requests: write` or the org policy from outside a run; it reports what it can.
- **Codex pricing table** in `lib/usage.mjs` is dated 2026-11-02 and carries guessed rates for gpt-6.1-sol and gpt-5.5; the bench's table should replace it and the date travels with the number into `result.json`.
- **Reviewer invocation.** Claude and Codex get a prompt saying "act as the reviewer agent in `<agents dir>/reviewer.*` and follow review-pr"; the model is `reviewer_model` on the command line because `-p` cannot spawn a named agent as the top-level session. Copilot gets `--agent reviewer`, which does read the pinned file. The reviewer runs in the PR's checkout so it can read the repository rules the skill names.
- **Doctor's App permission check** reads the installation's granted permissions when minting; Projects v2 appears as `organization_projects` on org installations and is checked under either key. Extra permissions WARN; missing ones FAIL.
- **Ruleset** uses `merge_queue` with SQUASH, ALLGREEN, 5-entry batches and a 60-minute check timeout, `required_status_checks` from `ci_checks` (strict), `pull_request` with zero required approvals (the reviewer is comment-only), `deletion` and `non_fast_forward`. Classic branch protection is read by doctor as a fallback but never written.
- **Secrets never reach a non-harness child**: `scrubbedEnv()` removes the model keys and the `FACTORY_INPUT_*` secret inputs before setup, install, validation and git hooks run. The Codex key is on the action's one step only and passed to the harness child only.

- The App flow end to end: JWT acceptance, `installation` lookup, `access_tokens` with `repositories`, the permission names in the reply, `[bot]` user lookup, and whether `pull_request(labeled)` by the App fires the review job while the job token's label would not.

- The issue dependencies REST endpoint (`/dependencies/blocked_by`) existing on the adopter's plan; the fallback is exercised by tests.
- Artifact download through `gh api .../zip` (binary stdout) and the `--slurp` page shape of `/actions/artifacts`.
- Federation: the exchange endpoint and reply shape are unknown; the code is a sketch behind an input.
- Six-hour jobs: the keeper's refresh, gh's `hosts.yml` honouring `GH_CONFIG_DIR`, and the git credential helper under `persist-credentials: false`.
- `actions/setup-node` and `npm install -g` of the harness packages on a hosted runner; the plugin location at the tag: `PLUGIN_ROOT` looks for `<action>/plugin` then `<action>/../plugin`, else `FACTORY_PLUGIN_ROOT` (lane 7 decides whether `action.yml` moves to the repository root).
- Mobile notifications from the App's @mention and review request (the plan's step 3 gate).
