# Factory director

Use this skill to operate the installed Factory plugin on a target repository. For adding features or fixing bugs in Factory itself, follow its contributor instructions instead.

Resolve the target repository and Objective issue number from the request. Refuse any Factory source, rebuild, or archive repository as a target. Read the target repository's own instructions and Objective; they remain the authority for scope and validation. Before any Objective command, including planning and status, confirm that the installed configuration binds the requested repository and checkout; an issue number alone is not repository identity. If the binding differs, stop and resolve it through setup without deleting existing state. Use `factory help` for the installed CLI surface. Keep controller scheduling inside Factory rather than reproducing it in chat or editing its state.

Run the controller through an authorized ordinary host launch while retaining worker sandbox, approval, credential and network safeguards; detached children still inherit an enclosing agent sandbox. Check [host and worker readiness](https://github.com/clockgrove/factory/blob/main/docs/USER-GUIDE.md#host-and-worker-readiness) before initial execution. Planning/login success is not worker-tool evidence. A socket-directory mask error requires stopping for host diagnosis, never chmod/unmask, a sandbox bypass or automatic worker retry. Ordinary plugin use operates the user's requested Objective; it does not require a Factory release fixture. Contributor qualification retains its separately defined gates.

For a setup request, use the packaged `setup` skill to select configuration-only or explicitly consented background operation through the guided entry point. Reuse supplied choices. Configuration-only requests stop before execution; background service consent alone permits model-free observation, and dispatch still needs an explicit Objective selection. For later batches use `intake enqueue --objective N [--objective N ...]` at a settled idle boundary under the existing owner, preserving failed/paused fences and terminal evidence. For a read-only planning preview, use `factory plan --objective N [--output ABSOLUTE_PRIVATE_FILE]`; show its pinned source packet, graph, review status, and any unresolved question. Inspect each proposed validation command and its source. The exact source-declared `pnpm install --frozen-lockfile --ignore-scripts` may bootstrap a fresh validation worktree before pnpm checks when the pinned target supplies a tracked lockfile; a plain install or a command absent from pinned sources has no authority. For execution, confirm the installed repository binding and the operator's request to run, then use `factory run --objective N`. It plans, saves the plan and its review in state, runs a clean plan within the configured autonomy limits, and exits when the Objective completes, fails or needs a human decision; report its final message. If the plan needs a decision, show the question from `factory status --objective N`, obtain the operator's specific answer or refusal and reason, record it on the exact plan status names with `factory decide --objective N --plan DIGEST --outcome accept|refuse --answer TEXT --reason TEXT` (refusing needs no `--answer`), then `factory run --objective N` again. A rerun never plans an existing plan again; a refusal discards it so the next run plans afresh. Do not call an unresolved plan runnable.

Use `factory status --objective N` to report progress, failure, final validation, a result decision, or a media selection pause. If an Objective pauses for media, read candidate IDs and digests from status; use `factory review --objective N --item ID --set SET_ID --output ABSOLUTE_NEW_DIRECTORY` for human review outside the target checkout. Obtain the human's whole-set selection, use `factory select --objective N --item ID --set SET_ID` with an optional reason and explicit `--bind` for each pending direct dependent that may consume the set, then run again. Respect target-owned Git LFS rules and never substitute unselected files. Structured source bindings can name pinned repository files, Objective-cited absolute private files, or recognized GitHub Objective attachments; never invent access, source identity, rights, or tool provenance.

If status names a pending Work Item or final Objective result criterion, show its exact tree, question, and evidence to the operator. The review packet uses bounded text excerpts with explicit truncation markers and blob descriptors for opaque files. A truncated text excerpt cannot auto-pass even if independent review reports pass. Show the affected paths and have the operator inspect the full tree before accepting; a larger `FACTORY_RESULT_REVIEW_TEXT_BUDGET_BYTES` and reviewer context may allow a fresh complete review. Obtain explicit acceptance or refusal and reason, then record `factory decide-result --objective N [--item ID] --tree EXACT_TREE_SHA --outcome accept|refuse --actor NAME --reason TEXT`. Include `--item` for a Work Item; omit it for final Objective acceptance. After an acceptance decision, resume with `factory run --objective N`. If the operator instead requests another automatic review after inspecting a failed or incomplete Work Item review, use `factory rereview --objective N --item ID --tree EXACT_TREE_SHA --actor NAME --reason TEXT`, then `factory run --objective N`. The request itself makes no model call and accepts nothing; run repeats validation/review of the preserved result without rerunning implementation. For a pending final Objective review, an authorized `factory run --objective N` already repeats final validation, hydration and automatic review; no item request is needed. Preserve existing per-run limits and prior usage, and stop to diagnose another failure rather than loop. A refusal stops delivery, and the decision applies only to that criterion and tree. Do not infer human acceptance from diagnostic events.

For a diagnosed known compiler-generated amendment rejection, including a completed independent review finding, use the existing `factory propose-amendment --objective N --proposal FILE` [replacement procedure](https://github.com/clockgrove/factory/blob/main/docs/USER-GUIDE.md#discover-required-work-during-a-run). Preserve the discovery, exact rejection binding, source obligations and started work. It requires paused settled ownership and an enabled planning repair class with remaining total/per-path allowance. Replacement leaves the Objective paused and accepts nothing; fresh compilation, validation and independent review must pass before projection. Unknown calls, invalid review responses, projected work, terminal state and unresolved source authority stay fenced.

For additions to an existing pnpm workspace, require exact package directories under `## Workspace package additions` in the pinned Objective. Inspect matching workspace/package ownership and the worker brief before execution. This declaration does not authorize changes to release-age policy or other package-manager security settings. See the [workspace membership instructions](https://github.com/clockgrove/factory/blob/main/docs/USER-GUIDE.md#add-packages-to-an-existing-pnpm-workspace).

For an agent-readable current state, use `factory status --objective N --json`. For a private timeline, use `factory diagnostics --objective N` or add `--follow` while a run is active. Model-invocation events distinguish compile, diagnosis, graph review, Work Item result review, and final Objective review; they expose real provider progress, configured model policy, provider thread identity, safe correlation digests, and usage only when supplied. A quiet timeline means the provider emitted no new event; do not invent a heartbeat or infer buffering. Use `factory diagnostics --objective N --summary` for invocation counts by phase/scope, available token totals, unavailable-usage count, and the exact cache-read numerator and denominator. Use `factory logs --objective N --item ID [--follow]` for that attempt's worker stdout/stderr. Stop following when enough evidence is available. These outputs may include private validation and worker content, so do not paste or publish them without review. The atomic snapshot returned through status remains the continuation authority; diagnostics never authorize retry or imply successful completion.

If the controller stops for any reason, run the Objective again: every step is safe to repeat, so issues, PRs and merges are never duplicated. Use `factory cancel --objective N` for an authorized stop and `factory retry --objective N --item ID` only for an explicitly authorized new attempt. Report the resulting status or refusal and return; do not poll indefinitely. Sandbox execution requires explicitly registered [application composition](https://github.com/clockgrove/factory/blob/main/docs/SANDBOX-EXECUTION.md); do not infer a bundled or qualified cloud provider.

Repair, re-review and amendment limits live in the optional `autonomy` section of the configuration ([limits](https://github.com/clockgrove/factory/blob/main/docs/USER-GUIDE.md#limit-unattended-work)); change them only at the operator's request. They cannot resolve a human-owned decision, and an Objective keeps the limits it started with.

A source-authorized Objective that qualifies existing committed content can use an all-QA graph with no implementation worker or delivery. The controller selects the unchanged pinned baseline as its candidate; it verifies the current default head before QA and final acceptance. Status and review identify that baseline basis explicitly. Do not invent a Work Item, PR or accepted predecessor to simulate integration. Mixed graphs continue to require actual integration and dependencies. Final acceptance still checks every original criterion and exact source-authorized command.

Planning supplies controller-local executable observations for the Objective's exact final commands. Ready confirms literal presence and executable access on the controller validation PATH only; it does not prove command success, runtime conditions or remote worker readiness. Unverified resolution stays unknown. Keep acceptance-only commands at their source-required validation phase; do not run them early to establish presence. Activation repeats the existing check.

Before treating a missing contract as a human decision, check authorized pinned sources for the omitted canonical material. Add an exact source selector through supported planning options and review the changed packet, preserving the rejected candidate. Ask about genuinely unspecified semantics; do not invent them or weaken acceptance to make a plan pass. Diagnose parser and prerequisite errors before another planning call.

For a requested Objective timing investigation, use `factory analyze --objective N --filter runId=EXACT_RUN --gantt --output ABSOLUTE_NEW_SVG` and save a separate `--json --output ABSOLUTE_NEW_JSON` report with the same selection. Follow the packaged [local analysis guide](../../docs/LOCAL-ANALYSIS.md). Choose existing private directories outside the target checkout; files must be unused and parents cannot be symlinks. Open the saved SVG locally, check its repository/Objective/run/item/attempt hierarchy and elapsed wall-clock axis, and use JSON to inspect recorded identities and missing endpoints. Labels show available provider, adapter, configured/reported model and validation-command index; executable names are unavailable when metadata does not record them. Never recover command names from private output or invent nested process timestamps. Direct executable invocation does not imply Bash; npm/node spans may include nested children without recording their individual lifetimes.

Interpret blue bars as retained Factory request-to-provider-terminal invocation boundaries, potentially including multiple model calls and tools, rather than model output fragments or exact HTTP requests. Amber starts derive from recorded operation durations; dots have no complete interval. Model, command and any recorded wait lanes can overlap and are not additive. CPU and network attribution remain unknown. Compare only the exact recorded source/run/workload boundary; absent child processes, endpoints or capture remain unavailable. The chart is debugging evidence, not live activity, ownership, acceptance or retry authority. Keep SVG and JSON private; do not publish real target traces without separate review.

Approved graph projection applies `factory:objective` to the Objective and `factory:work-item` to every compiled work, QA or aggregate issue, preserving unrelated labels. Missing repository role labels are created with neutral `ededed` color; existing label presentation stays unchanged. Archived or ambiguous labels require an operator decision, never automatic renaming or unarchiving. Ordinary and QA Work Items attach as native Objective children; aggregate children attach to their aggregate. Parent context and dependency edges remain distinct and grant no execution or acceptance authority. Projection resumes from authenticated existing identities and refuses changed bodies, duplicate markers, conflicting parents or ambiguous metadata; do not manually relabel or reparent an uncertain run to force continuation.
